# 架构与模块地图

## 一句话结构

`tidy.py` 一个文件从上到下依次是：常量与路径 → 设置读写 → `Rules` 与分类 → 扫描与移动 →
卸载 → 计划任务 → 截图清理 → 缓存清理 → 预览与帮助 → 自启 → 托盘 → 单实例 → 迁移与搜索 →
右键菜单 → `run_gui()`（GUI 主体，4542 行）→ `main()`（入口分发）。

`run_gui()` 内部的顺序是：窗口与主题 → 8 个页面的构造 → 首次关窗询问/托盘启动 →
`root.mainloop()`。页面之间靠闭包共享变量，没有类，也没有消息总线。

## 启动链路

```
main()
 ├─ detect_gui_build()         判断是打包 --windowed 还是源码跑
 ├─ hide_console()             源码模式：把控制台藏起来（打包后无控制台，跳过）
 ├─ 有 --migrate / --cli 等参数 → run_cli() / migrate_data() 等，不建窗口
 └─ 无参数或 --tray
     ├─ _claim_single_instance()     互斥体 TidyHelper_MainInstance
     │   └─ 已有实例 → _signal_show_existing() 触发命名事件，自己退出（退出码 0）
     ├─ --tray 且没有目录参数 → run_gui(tray_only=True)：先 withdraw 再建控件，全程不显窗
     └─ 否则                    → run_gui(prefill=prefill_dir(argv))
```

`run_gui()` 尾部：`start_show_listener()` 起后台线程等命名事件，主线程用
`root.after(400, _poll_show)` 收旗 → `_show_main()` 把窗口叫出来。**不能**在线程里直接
`root.after()`，会抛 `RuntimeError: main thread is not in main loop`。

`--tray` 但托盘起不来（`_tray["ok"]` 为假）时，会 `root.deiconify()` 把窗口显示出来并写
`数据\tray.log`，避免留下一个叫不出来的隐藏进程。

| `recursive_depth` | `3` | 递归层数上限 |
| `log_keep_days` | `30` | 日志保留天数 |
| `everything_path` | `""` | es.exe 路径，空则不用 |

**兼容规则**：`load_settings()` 发现 `close_action` 不是三态之一时，按旧的 `close_to_tray`
映射（True→tray / False→exit），并把 `close_choice_made` 置 False——让老用户第一次关窗时被问一次。

## 数据目录

```
数据\
├── 配置\settings.json      SETTINGS_PATH，便携模式优先 exe 旁边
├── history\                每次整理的 JSON 历史（可撤销）
├── logs\                   运行日志
├── 卸载备份\               卸载前导出的 .reg
├── cache\fileindex.db      搜索索引（SQLite）
├── 缓存清理.log            每次缓存清理的计数 + 失败明细
└── tray.log                托盘、钉子、单实例的诊断输出
```

`SETTINGS_DIR` 的兜底链：`数据\配置` → 不可写则 `%APPDATA%\整理助手`。
`DEFAULT_DATA` 的兜底链：`exe旁边\数据` → 不可写则 `%LOCALAPPDATA%\整理助手`。

## 关键机制

### 安全拦截（三类整棵子树放弃）
`detect_program_folder`（程序目录）、`detect_project_folder`（18 种工程标志文件）、
`detect_source_folder`（源码目录）任一命中，该目录整棵子树都不处理，不进预览也不移动。
递归深度默认 3 层，超过就停。

### 分类
14 类按扩展名（`Rules.ext_to_cat`），5 类按内容（`classify_content`）：
强特征词 2 分、普通词 1 分，满 5 分才改判类型。文本抽取走 `extract_text`，
PDF 用 pdfminer、docx 用 python-docx。

### 撤销
每次 `apply` 前把「原路径 → 新路径」写进 `history\*.json`，`undo` 逆序搬回。
只覆盖本工具自己移动过的文件。

### 关窗三态
`on_close` → `_close_action_now()`：托盘不可用就直接退出；`ask` 或用户还没做过选择
就弹 `_ask_close_action()`；选了 tray 就 `withdraw()`。询问窗里
**回车 / Esc / 右上角 × 一律按「最小化到托盘」**——直接退出不可逆，不该是默认动作。

### 托盘图标位置（`tray_pin`）
Windows 把图标放在任务栏还是 `^` 折叠区，由
`HKCU\Control Panel\NotifyIconSettings\<hash>\IsPromoted` 决定。
`apply_tray_pin()` 按 `os.path.normcase(sys.executable)` 匹配到自己的键：

| `tray_pin` | 写入 | 说明 |
|---|---|---|
| `taskbar`（默认） | `IsPromoted=1` | 关窗缩下去就能在任务栏看到 |
| `overflow` | `IsPromoted=0` | 只占折叠区 |
| `system` | 不写 | 完全交给用户拖动 |

写完用 `get_tray_promoted()` 读回，返回 `(写入次数, 仍不对的键名列表)`；
有残留就 `root.after(1500, ...)` 重试，最多 3 次，每次都往 `数据\tray.log`
写 `tray_pin mode=... try=... wrote=... bad=...`。
一个自己的键都没匹配到不算写过（源码版和 exe 版各管自己那条）。

### 缓存清理的失败明细
`clean_cache_paths` 返回的失败项是 `(路径, 原因)`，原因由 `_fail_reason(ex)` 把
WinError 译成中文。`run_clean_cache` 往 `缓存清理.log` 追加最多 40 行
`    ! <路径>  <- <原因>`，GUI 显示前 12 条。删前先 `_clear_readonly` 去只读位，
删不动再用 `_remove_file_stubborn` 单文件重试，目录用 `_rm_tree_reported` 逐文件定位卡住的那个。
