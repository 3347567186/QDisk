# 踩坑与设计决策

按「坑 → 现象 → 根因 → 现在怎么做的」记。改代码之前扫一眼，能省掉重新踩一次的半天。

## 1. `is_junction()` 是 Python 3.12 才有的

**现象**：缓存清理在 3.11 上直接崩，`AttributeError: 'nt.DirEntry' object has no attribute 'is_junction'`。

**根因**：`_tree_size` 里写的是 `e.is_symlink() or e.is_junction()`，后者 3.12 才加。

**现在**：模块级 `FILE_ATTRIBUTE_REPARSE_POINT = 0x400` + `_entry_is_link(e)`，
用 `stat(follow_symlinks=False)` 的 `st_file_attributes` 判重解析点，两个版本都能跑。

**教训**：便携工具要照顾用户当前的解释器版本，别用「我这儿有」的 API。

---

## 2. 启动秒退、没有任何日志

**现象**：改了代码跑 `py -3 tidy.py`，进程立刻退出码 0，窗口不出现，`tray.log` 一行不加。
看起来像「启动就崩了，而且崩得连异常都没有」。

**根因**：单实例互斥体 `Local\TidyHelper_MainInstance` 被**上一轮测试留下的 exe 实例**占着。
`main()` 发现互斥体已存在 → `_signal_show_existing()` → 自己静默退出。代码完全正常。

**怎么确认**：`OpenMutexW` 直接探（见 `_claim_single_instance` 的探活写法），或者
`Get-Process | Where-Object { $_.ProcessName -like '*整理*' }` 看有没有残留 exe。

**现在**：跑测试前先清场（见 [测试清单](测试清单.md) 最后一节）。

**教训**：GUI 程序的「静默退出」优先怀疑单实例闸，别怀疑逻辑。

---

## 3. 中文进程名在 bash 里查不到

**现象**：`Get-Process -Name 整理助手` 无输出，误判「没有进程在跑」。

**根因**：bash 传中文参数给 PowerShell 时编码被改，名字匹配不上。

**现在**：用通配符 `-like '*整理*'`，或者走 `Get-CimInstance Win32_Process` 按
`ExecutablePath` 过滤。

---

## 4. `sys.executable` 是启动器壳，pid 不等于窗口宿主

**现象**：`Popen([sys.executable, "tidy.py"])` 拿到的 `p.pid` 去 `EnumWindows` 找窗口，
一个都找不到；`p.poll()` 立刻返回 0，看起来程序已经退了，可窗口还在。

**根因**：venv 里的 `python.exe` 只是壳，真正的界面跑在它拉起的另一个 python 进程里。
`Popen` 的 pid 是壳的。

**现在**：一律「按窗口标题做 hwnd 前后差集」，不看 pid。打包后的 exe 没有这个问题
（onefile 是父引导器 + 子进程，两个 PID 都属于同一个逻辑实例）。

---

## 5. `EnumWindows` 的 argtypes 写错会静默漏结果

**现象**：回调声明成 `c_void_p` 时，枚举「成功」但拿到垃圾句柄/漏掉全部窗口。

**现在**：

```python
CT = ctypes.WINFUNCTYPE          # 不要用 windll.user32.WINFUNCTYPE，3.14 上没有
u.EnumWindows.argtypes = [CT(ctypes.c_int, ctypes.c_void_p, ctypes.c_void_p), ctypes.c_void_p]
```

**同类问题**：所有 `ctypes` 调用都要显式写 `restype`/`argtypes`，默认 `c_int` 会把
64 位句柄截断成垃圾（`_kernel32()` 就是这么写的）。

---

## 6. 从外部 `ShowWindow` 唤不醒 Tk 的窗口

**现象**：第一版单实例用 `FindWindowW + ShowWindow(9)` 唤醒已有窗口，窗口「显示」了，
但用户点它没反应，像是画上去的。

**根因**：窗口是 Tk 自己 `withdraw()` 的。外部 `ShowWindow` 只改了 Win32 的可见性，
Tk 内部状态还是「隐藏」，事件循环不认。

**现在**：互斥体判重 + 命名事件。第二个实例 `SetEvent`，第一个实例的后台线程
（`start_show_listener`）收到后**插旗**，主线程用 `root.after(400, _poll_show)` 收旗再
`deiconify()`。

**另一个坑**：别在线程里直接 `root.after(0, ...)`，会抛
`RuntimeError: main thread is not in main loop`。线程只能写一个普通变量。

---

## 7. 托盘图标会自己从折叠区跳回任务栏

**现象**：把图标拖进 `^` 折叠区，重启程序它又回到任务栏。

**根因**：老代码 `promote_tray_icon()` 在托盘建好后写
`HKCU\Control Panel\NotifyIconSettings\<hash>\IsPromoted = 1`，**每次启动都钉回去**。

**现在**：删掉 `promote_tray_icon`，改成一次性的 `unpin_tray_once()`：
按 `sys.executable` 的 `normcase` 路径匹配自己的键，清 `IsPromoted` 为 0，
然后 `get_tray_promoted()` **读回校验**；全 0 才写 `tray_unpinned=True`（下次不再动）。
一个自己的键都没匹配到**不算做过**——否则源码版会把自己的那次「做完」了，exe 的键永远漏掉。

**教训**：动注册表要「写 → 读回 → 才算成功」，不能只按「调用没抛异常」就当成功。

---

## 8. 关窗询问窗默认选中了「直接退出」

**现象**：截图检查询问窗时发现「直接退出」抢了焦点，用户按回车就把正在跑的任务退掉了。

**现在**：`<Return>` 绑到 `pick("tray")`，`grab_set()` 之后显式 `btn_tray.focus_set()`；
`WM_DELETE_WINDOW`、`Esc`、右上角 × 也一律按托盘处理。

**理由**：误关到托盘最坏是「程序还在后台」，误关成退出会把正在跑的整理任务拔掉。
两个方向的代价不对称，所以默认永远选代价小的那个。

---

## 9. 设置页分组默认折叠

**决策**：五张卡片（目录位置 / 默认行为 / 索引目录 / 右键菜单 / 开机自启）默认收起，
点标题行展开。

**为什么**：这些设置一次配完就很少再改，全展开会把页面撑成一条长滚动条，
每次进设置页都要滚。收起后五条标题一屏看完，也看得见「有这么几类设置」。

**实现**：`card(parent, title, opened=True, hint="")`，`opened=False` 时 body 不 pack、
箭头画 `▸`。

---

## 10. `PrintWindow` 抓到的是黑图 / 全屏截图抓到别的程序

**现象**：想自动截图检查界面，`ImageGrab.grab()` 全屏抓到的是后台别的窗口；
`PrintWindow` + `CreateCompatibleBitmap` 返回成功，转存却报
`InvokeMethodOnNull`（PowerShell 的 `Bitmap.FromHbitmap` 拿不到位图）。

**现在**：三步走——按标题找 hwnd → `ShowWindow(9)` + `SetForegroundWindow` → 等 1 秒再
`PIL.ImageGrab.grab(bbox=窗口矩形)`。顺手用 `TIDY_TAB=6` 直接进要截的那一页。

---

## 11. 缓存清理「失败 73 个」查不出所以然

**现象**：`数据\缓存清理.log` 里失败数一直涨（24 → 25 → 32 → 60 → 73），
日志只有个数，没有路径没有原因。

**现在**：`clean_cache_paths` 返回 `(路径, 原因)`；`_fail_reason(ex)` 把 WinError
翻成中文（32 被占用 / 5 拒绝访问 / 145 目录非空 / 206 路径过长 / 267 盘符无效 / 1392 文件损坏…）；
日志追加最多 40 行明细，GUI 显示前 12 条。删前 `_clear_readonly` 去只读位，
单文件用 `_remove_file_stubborn` 重试一次，目录用 `_rm_tree_reported` 逐文件定位。

**教训**：批处理失败只报个数等于没报。至少给出「第一个失败的是谁、为什么」。

---

## 12. 一个函数 4542 行，改起来靠锚点

`run_gui()` 从 4428 到 9004，内部一百多个闭包，共享几十个局部变量。这是「单文件便携」
的代价，短期不打算拆（拆了要动几百处引用，风险远大于收益）。

**所以批量改动一律走补丁脚本**：写一个 `_patch*.py`，对每个改动点先断言锚点唯一
（`src.count(anchor) == 1`），不唯一就 `sys.exit`，确认唯一再替换，最后 `py_compile` 校验。
直接手改四千行里的十处，漏一处很难发现。

改完记得 `rm _patch*.py`——它们是一次性的，留在目录里只会让人误以为还要跑。

---

## 13. bash 里写含反斜杠的脚本会被吃层

**现象**：用 heredoc 写 Python 补丁脚本，`\\` 变成 `\`，写进文件的路径全错。

**现在**：长脚本（尤其含反斜杠、中文、引号）先用 `write` 工具落成文件再执行，
不要塞进 heredoc。

---

## 14. 关窗进了后台，托盘里就是看不到图标

**现象**：`数据\tray.log` 里 `tray_ok=True`，进程也活着，可任务栏没有图标。

**根因**：注册表 `HKCU\Control Panel\NotifyIconSettings\<键>` 的 `IsPromoted=0` 表示图标被
Windows 收进 `^` 折叠区。上一版为了修「拖进折叠区又被弹回任务栏」，启动时**强制写 0**，
于是每次都藏起来。截图对比可证：同一进程写 `IsPromoted=1` 后任务栏立刻出现图标。

**现在**：`tray_pin` 三态（`taskbar` / `overflow` / `system`），默认 `taskbar`；
`apply_tray_pin()` 写完用 `get_tray_promoted()` 读回，没写成功就重试 3 次并记日志；
`system` 完全不碰注册表。键按 `os.path.normcase(sys.executable)` 匹配 `ExecutablePath`，
所以源码版和 exe 版各管自己那一条，不会互相覆盖。

**教训**：自动化「替用户决定 UI 位置」这类改动，必须留一个「不做」的选项，
而且写到注册表的东西要能读回验证。

## 15. 托盘图标是个蓝方块

**现象**：托盘显示纯蓝色方块，不是 `icon.ico`。

**根因**：托盘代码 `_res("icon.ico")` 在 `_MEIPASS` 里找不到文件，于是 `Image.new(...)`
画了个 `(47,111,221)` 的方块兜底。打包命令原来只有 `--icon icon.ico`（设 exe 图标），
没有 `--add-data "icon.ico;."`（把文件放进包里）。

**现在**：打包命令加了 `--add-data "icon.ico;."`；`_res()` 在 `_MEIPASS` 找不到时
退回 `os.path.join(HERE, name)`，源码模式和打包模式走同一条路。

**教训**：`--icon` 和 `--add-data` 是两件事，前者只改 exe 资源，后者才让代码能读到文件。

---

## 16. `Could not create temporary directory!`（onefile 起不来）

见 `打包与发布.md` 的「已知环境坑」一节。简版：同一份 exe 换个目录就能跑，
排除掉 TEMP、`--runtime-tmpdir`、ACL、杀毒之后，仍是目录级环境问题；
`--onedir` 版在同目录能跑，说明卡在 onefile 解压临时目录那一步。

**排查套路**：先用 `--debug=all` 构建一个 console 版（`--onefile` 不加 `--windowed`），
直接看 bootloader 停在哪一行；windowed 版只会弹一个没信息量的 `Error` 对话框。
再拿同一份二进制到不同目录做对照，能立刻分清「代码问题」还是「目录环境问题」。
