## 0. 摘要

第一轮把 9 个页面从 WPF 迁到 Tauri 并跑通，验证了「Rust 外壳 + WebView2 前端 + Python 引擎」这条链路，安装包从 96.2 MiB 降到 36.6 MiB。

第二轮不是加功能，而是把「能用」变成「好用」：重排布局与信息密度、补齐截图/卸载/设置的可用性、统一右键菜单与预览能力、修掉缩放与滚动、全局禁选文字、清掉旧框架残留。本文把用户的 9 条意见拆成可验收的需求项，给出逐页改造清单、技术接口、分阶段排期和发布迁移步骤。

结论先说：

1. 用户提的 9 条全部成立，其中 5 条是「功能性缺陷」（截图扫描、卸载、设置、滚动/缩放、右键菜单），4 条是「设计/工程质量」（密度、留白、禁选、旧残留）。
2. 现有前端骨架（`styles.css` / `index.html` / `ui.js` / `app.js`）已在上一轮重写到位，本轮主要是**页面级重排 + 少量 Rust 命令 + 发布流程收口**，不需要推翻架构。
3. 最大的不确定性是 WebView2 的文本选择/右键行为与 Windows 高 DPI 缩放，需要真机回归；其次是把旧版本清干净时别误删正在使用的安装目录。

### 1.2 需求拆解与验收标准

#### R1 重排布局、提升信息密度

现状问题：
- 整理页是「一列到底」，扫描选项与预览列表各占一张大卡片，上下滚动很长，首屏只看到 2 个控件。
- 顶部标题区 `page-sub` 与卡片标题重复，右侧动作按钮与卡片内容争抢横向空间。
- 每页左右各留 24px、卡片内再留 16px、表格行高 44px，实际内容宽度被压到约 60%。

目标：
- 每页采用「顶部一行工具栏 + 主体左右分栏（列表 / 详情或选项）」结构，横向利用率 ≥ 85%。
- 首屏必须看到该页的主操作和主数据；设置类页面默认折叠，只露出分组标题与当前值。
- 表格行高从 44 → 34–36；卡片内边距 16 → 12；页面左右留白 24 → 16（窗口 ≥ 1200 时 20）。
- 侧栏在窗口 < 1100 时自动折叠为图标条（可手动锁定），内容区不再被 208px 固定宽度挤压。

验收：
- 1280×800、1440×900、1920×1080 三档分辨率下，无横向滚动条、无内容截断。
- 整理页首屏可见：路径输入、扫描/整理按钮、扫描选项摘要、预览统计；不需要滚动即可点「扫描」。
- 卸载页首屏可见 ≥ 8 行数据行。

#### R2 清理截图：多目录 + 预览 + 适配

现状问题：
- 引擎 `shots.scan` 默认扫 `Pictures`、`Pictures\Screenshots`、`Desktop`、`Downloads` 四个目录，页面没有目录管理入口，用户想加 `D:\截图` 无从下手。
- 列表是纯文本行，没有缩略图；没有大图预览。
- 扫描结果很大时（数千张）一次性渲染会卡。

目标：
- 目录管理：页头「目录」按钮打开目录清单，可添加/移除/恢复默认，写入配置（Rust 侧 `shot_dirs`），扫描时作为 `dirs` 参数传给引擎。
- 缩略图网格：每张 160×120 卡片，显示文件名、大小、修改时间、所属目录；懒加载（`IntersectionObserver`），滚动不卡。
- 预览器：单击打开全屏预览，支持左右切换、滚轮缩放、双击 1:1、Esc 关闭、键盘 ←/→/+/-，可「定位到资源管理器」。
- 兼容：路径含空格/中文/长路径；HEIC/WebP 等非原生格式显示占位图并给「用系统应用打开」；损坏图片不阻塞整个网格。

验收：
- 添加 `D:\截图测试` 后重新扫描，结果包含该目录图片。
- 1000 张截图下滚动帧率 ≥ 50fps，内存增长 < 150 MB。
- 预览大图 ≤ 200 ms 打开，切换 ≤ 100 ms。

#### R3 卸载程序可用、显示图标、管理员入口

现状问题：
- `apps.uninstall` 调引擎后会启动系统卸载器，但页面未处理返回，用户看不到反馈；部分条目 `uninstall:false` 仍显示「卸载」按钮。
- 列表只有名称/版本/发行商/路径，没有图标。
- 读取 HKLM 下的软件需要管理员权限，普通权限下部分条目信息不全。

目标：
- 图标：优先用引擎返回的 `icon`（exe 路径）通过 `convertFileSrc` 显示；无图标时用首字母色块。
- 卸载：点击后弹确认框（显示名称/版本/发行商），调用 `apps.uninstall`；返回后提示「已启动系统卸载器」，并刷新列表（延迟 2 s）。
- 无卸载器条目：禁用按钮并提示「该系统项没有卸载命令，可尝试清理残留」。
- 管理员：页头显示权限状态徽标（管理员/普通），普通权限时出现「以管理员身份重启」按钮，调用 Rust `run_as_admin`；重启后窗口隐藏、新进程接管。
- 残留扫描：选中条目后 `apps.leftovers` 展示目录/注册表项，支持「清理残留」。

验收：
- 普通权限下点击「以管理员身份重启」→ UAC 弹窗 → 新实例为管理员，页面徽标变化。
- 有卸载器的条目点击卸载 → 系统卸载程序出现；无卸载器的按钮置灰。
- 图标显示覆盖率 ≥ 70%（本机 140 项抽样）。

#### R4 设置页压缩、折叠、真正生效

现状问题：
- 四个大卡片纵向排列，一屏放不下；数据目录、递归深度等设置「保存」后需重启页面才刷新。
- 主题/语言/关闭行为/自启动/定时任务混在一起，没有分组层级。

目标：
- 改为「左分组导航 + 右内容」或「手风琴分组」：外观与语言 / 行为与启动 / 整理默认值 / 数据与日志 / 定时整理 / 关于。
- 默认只展开「外观与语言」，其余显示一行摘要（如「递归深度 3 · 冲突重命名」）。
- 所有开关即时生效并 toast 反馈；不需要「保存」按钮的项（主题、语言、关闭行为）去掉保存；需要保存的（数据目录、深度等）在分组内提供「保存」。
- 修改数据目录后，提示「需要重启引擎生效」，提供「立即重启引擎」按钮（`engine_restart`）。

验收：
- 设置页首屏可见 6 个分组标题，无需滚动。
- 修改任一项后重新进入页面，值保持。
- 主题/语言切换 < 300 ms 生效。

#### R6 缩放/最大化/全屏适配 + 滚轮滚动

现状问题（根因已知）：
- 旧布局让 `body` 成为滚动容器，页面内容高度由内容撑开，WebView2 下滚轮事件落在非滚动容器上 → 滚不动。
- 窗口最大化后内容区没有 `min-height:0`，grid 子项溢出被裁切。
- 部分页面用 `height:100vh`，缩放后底部被任务栏遮住。

目标：
- 唯一滚动容器 `#scroll`（`overflow-y:auto; min-height:0; scrollbar-gutter:stable`），`html/body` 设 `overflow:hidden`。
- 所有页面根节点 `height:100%`，内部表格区域用 `flex:1; min-height:0`。
- 监听 `window.resize`，侧栏 < 1100px 自动收起；表格列在小宽度下隐藏次要列。
- 全屏（F11 由 WebView2 处理）与最大化下无横向滚动。
- 滚轮在任意区域都能滚动主容器（除表格自身横向滚动条）。

验收：
- 1280×720 / 1920×1080 / 最大化 / 全屏，四态下滚轮均可用。
- 缩放 100%/125%/150% 下无重叠、无截断。

#### R7 全局禁选文字（按用户指定实现）

CSS（带注释与演示）：

```css
/* 全局禁止文本选中：桌面应用观感。
   - 输入框、文本域、可编辑区域必须保留选择能力，否则无法编辑。
   - 兼容 Chromium/WebKit/Firefox/旧 Edge 前缀。 */
*,
*::before,
*::after {
  -webkit-user-select: none;   /* Safari / 旧 Chromium */
  -moz-user-select: none;      /* Firefox */
  -ms-user-select: none;       /* 旧 Edge / IE */
  user-select: none;
}

input,
textarea,
select,
[contenteditable="true"],
[contenteditable=""] {
  -webkit-user-select: text;
  -moz-user-select: text;
  -ms-user-select: text;
  user-select: text;
}

body {
  -webkit-touch-callout: none; /* 长按不弹系统菜单 */
}
```

配套：
- 全局 `contextmenu` 捕获阶段 `preventDefault()`，输入控件与 `[contenteditable]` 除外；页面用 `UI.attachMenu()` 绑定自绘菜单。
- 演示区：设置页「关于」分组内放一段说明文字 + 一个输入框，用于验证「文字不可选、输入框可选」。

验收：任意页面拖动鼠标不出现蓝色选区；输入框内可正常选中/复制；右键出的是自绘菜单。

## 3. 设计方案

### 3.1 信息架构

侧栏 9 项保持不变（整理文件、清理截图、清理缓存、搜索文件、高级规则、卸载程序、数据迁移、日志、设置），但：
- 侧栏宽度 208 → 196（展开）/ 56（折叠）。
- 分组：日常（整理、截图、缓存、搜索）｜进阶（规则、卸载、迁移）｜系统（日志、设置），组间 12px 分隔。

### 3.2 栅格与密度

| 令牌 | 现值 | 新值 |
|---|---|---|
| 页面左右留白 | 24 | 16（≥1200px 时 20） |
| 卡片内边距 | 16 | 12 |
| 卡片间距 | 16 | 12 |
| 表格行高 | 44 | 34 |
| 控件高度 | 34 | 32 |
| 字号 | 13/12/11 | 13/12/11 不变 |
| 圆角 | 6 | 6 不变 |

三档断点：≥1280 双栏；1024–1279 单栏 + 侧栏折叠；<1024 侧栏图标条、表格隐藏次要列。

### 3.3 页面骨架模板

```
.page
 ├─ .page-head       标题 + 副标题 + 右侧主操作
 ├─ .page-tool      工具栏（搜索/筛选/视图切换/批量操作）
 ├─ .page-main      flex:1; min-height:0; 分栏或列表
 │   ├─ .pane-list  列表/网格（overflow:auto）
 │   └─ .pane-side  详情/选项（可折叠）
 └─ .page-foot      统计与分页（可选）
```

### 3.4 右键菜单矩阵

见 1.2 R5 表格。实现：`UI.attachMenu(el, items | (evt) => items)`，菜单容器 `#ctx-root`，`position:fixed`，越界自动翻转。

### 3.5 预览器

- 底部：缩略图条（当前项高亮）、上一张/下一张、缩放百分比、定位按钮。

## 8. 构建、发布与迁移

### 8.1 构建前提（不可省略）

1. 源码路径必须 ASCII：`D:\Tool\tidy-src` → `11_Tauri正式版` 的 junction。
2. `CARGO_TARGET_DIR=D:\Tool\tidy-build`（ASCII）。
3. `RUSTUP_TOOLCHAIN=gnu-d`（`D:\Tool\rust-gnu`），`CARGO_HOME=D:\Tool\cargo-ascii`。
4. `PATH` 前置 `D:\Tool\binutils\mingw64\bin`。
5. 图标必须是 ASCII 绝对路径（`D:/Tool/tidy-icons/icon.ico`）。

### 8.2 构建命令

```powershell
cd D:\Tool\tidy-src\src-tauri
$env:RUSTUP_TOOLCHAIN='gnu-d'
$env:CARGO_HOME='D:\Tool\cargo-ascii'
$env:CARGO_TARGET_DIR='D:\Tool\tidy-build'
$env:Path='D:\Tool\binutils\mingw64\bin;' + $env:Path
& 'D:\Tool\整理助手\缓存\tauri-cli\bin\cargo-tauri.exe' build --bundles nsis
```

产物：`D:\Tool\tidy-build\x86_64-pc-windows-gnu\release\bundle\nsis\TidyAssistant_<ver>_x64-setup.exe`。

2. 覆盖 `D:\Tools\TidyAssistant\tidy-assistant.exe`（引擎无需变更时不动 `引擎\`）。
3. 校验快捷方式目标仍为 `D:\Tools\TidyAssistant\tidy-assistant.exe`。

5. 安装包重新生成后，用 `/S /D=D:\Tools\TidyAssistant` 静默安装验证一次全新安装路径。

### 8.4 便携包

`整理助手_<ver>_便携版.zip` = `tidy-assistant.exe` + `引擎\` + `WebView2Loader.dll` + `使用说明.txt`；解压即用，数据仍写 `%LOCALAPPDATA%\整理助手数据`。
