# 整理助手

把「一个文件夹里散落的各种文件」按类型就地收进分类子文件夹。
**不删除任何文件，不动已有子文件夹，不碰程序目录 / 代码工程 / 源码目录 / 系统目录。**

绿色便携版，解压双击即用，不用安装。规则内置，依赖内置，**永远不会弹出黑色终端窗口**。

---

## 目录里有什么

```
整理助手\
├── 整理助手.exe   ← 双击运行。约 13 MB
├── _internal\     ← 运行时依赖，和 exe 放一起，删了打不开
├── 数据位置.json  ← 自动生成：记着数据目录在哪
├── 首次使用.txt   ← 解压后先看这个，三句话说清怎么开始
├── 数据\         ← 自动生成：配置、历史、日志、卸载备份、搜索索引、迁移任务
├── rules.json    ← 可选。放在旁边就能覆盖内置规则
├── 说明.md       ← 这份使用手册
├── icon.ico      ← 图标（exe 里已内嵌）
└── 第三方许可.txt
```

装在「源码与开发文档」包里时还会多出 `tidy.py`、`migrate_engine.py`、`test_*.py`
和 `开发文档\` —— 那是给改代码的人看的，日常使用不需要它们。

**便携模式**：数据默认放在 exe 旁边的 数据\ 里，配置跟着数据目录走
（`数据\配置\settings.json`），不写注册表。数据目录可以改到别处，
程序目录里的 `数据位置.json` 记着它在哪。
程序目录不可写时，配置退回 %APPDATA%\整理助手，指针退回 %LOCALAPPDATA%\整理助手。
把整个文件夹连同数据目录一起拷走，历史记录和设置都跟着走。

exe 和 `_internal\` 要放在一起，单独拷 exe 打不开。

## 设置页：数据位置可迁移

配置跟着数据目录走：数据目录是 `D:\我的数据`，配置就是 `D:\我的数据\配置\settings.json`；
默认数据目录是 `exe 同级\数据`，配置就是 `数据\配置\settings.json`。
`配置` 目录写不进去时，退到 %APPDATA%\整理助手。

程序目录里还有一个 `数据位置.json` 指路，内容形如
`{"data_dir": "D:\\我的数据", "updated": "2026-11-13 10:00:00"}`。
源码运行时它在 `07_代码配置\`，打包后它在 `整理助手.exe` 旁边；写不进程序目录时退到
%LOCALAPPDATA%\整理助手\数据位置.json。下次启动按它找数据目录。

换机器时，拷整个数据目录最省事；也可以在新机器上打开设置重新指定数据目录。

| 项 | 说明 |
|---|---|
| 数据目录 | 历史、日志、卸载备份、迁移任务的根。默认 `exe 同级\数据`，可改成任意位置 |
| 缓存目录 | 搜索索引放这儿，留空就用「数据目录\cache」 |
| Everything 路径 | 可自动检测 |
| 默认重名策略 / 递归深度 / 日志保留天数 | 新会话默认值 |
| 默认勾选「包含子文件夹」「按内容识别」 | 启动时的默认状态 |
| 索引目录 | 搜索索引覆盖哪些根，可增删 |
| 点关闭按钮时 | 三选一：最小化到托盘 / 直接退出 / 每次询问（第一次关窗会问一次，勾「记住」后不再问） |
| 托盘图标位置 | 三选一：始终显示在任务栏（默认）/ 只放在折叠区里 / 跟随系统（完全交给 Windows，你拖哪就是哪） |

设置页的五个分组（目录位置 / 默认行为 / 索引目录 / 右键菜单 / 开机自启）**默认都是收起的**，
点标题行展开 —— 一屏就能看到所有分组，不用先滚一遍。

**点「保存设置」立即生效**，落盘之后才单独问要不要搬旧数据：

- 选「是」：后台搬整个旧数据目录，底部进度条显示进展。`配置` 子目录不搬，配置由保存流程放到新位置
- 选「否」：只是不搬文件，设置照样保存生效；旧文件留在原处，不会自动删除
- 迁移是递归合并：目标里已有同名项不覆盖，记为失败。全部成功时日志写「迁移完成，旧目录可以自己删」，并列出搬了几项
- 有失败会弹「迁移未全部完成」，没搬成的仍留在旧目录

数据目录会先校验，下面这些会被拒，弹「数据目录不可用」并说明原因，输入框回填原值：

- 空
- 盘符根目录，如 `C:\`
- 文件路径
- 程序目录本身（可以放它的子目录，比如 `数据\`）
- 新目录在旧数据目录里面
- 不可写的目录

启动时如果 `数据位置.json` 指向的目录不在了（移动硬盘没接、目录被删或被改名），
先弹「数据目录找不到」，写明原路径和这次用的默认目录，然后用默认目录继续。
把盘接回或目录恢复后重启即可，也可以到设置里重新指定。

目录位置卡片底部有一行灰字说明这件事，下面还有「配置文件：…」标签，改完保存后会跟着变。

### 资源管理器右键菜单

设置页底部有「安装 / 移除」按钮。安装后：

- 在任意文件夹上右键 → **用整理助手整理**
- 在文件夹空白处右键 → 同上
- 在磁盘盘符上右键 → 同上

点击后会用该路径打开界面并自动扫描（不是直接动手，仍需你确认）。

写的是 `HKCU\Software\Classes`，**不需要管理员**。点「移除」三个键全部删净，不留残留。
实测往返验证过：注册 → 读回 → 移除 → 无残留。

## 搜索页

**不装 Everything 也能用。** 搜索有两条后端，按可用性自动选择：

### ① 本地索引（永远可用，默认）

自己建的文件名索引，SQLite 存在 `缓存目录\fileindex.db`，只存
文件名 / 路径 / 大小 / 修改时间，**不读文件内容、不联网**。

第一次用有两种方式建立：

- 搜索页直接搜 → 检测到没有索引会问你要不要建，点「是」自动索引桌面 / 文档 / 下载
- 或者到「设置 → 索引常用位置」

想要全盘，设置里另有「整盘索引」按钮（D / E），会先弹提示告诉你代价：

| 范围 | 文件数 | 建库耗时 | 索引体积 | 单次搜索 |
|---|---:|---:|---:|---:|
| 桌面 + 文档 + 下载 | 几千 | 几秒 | 几 MB | 毫秒级 |
| 整盘 D + E | 128 万 | 126 秒 | 223 MB | 0.25 秒 |

> 搜索先在**文件名**里找；文件名没命中才会回退到**完整路径**匹配，
> 那次回退要全表扫，约 1.5 秒。

之后可以随时「重建索引」刷新；双击结果直接打开所在文件夹。

### ② es.exe（如果装了）

Everything 的命令行版。放在 `Everything.exe` 同目录或 PATH 里会被自动发现，
命中时优先走它——整盘秒出，且用的是它自己维护的实时索引。

### 关于「内置 Everything」

我查了你这个担心，先说结论：

- **Everything 是 MIT 协议**（官网 License.txt 就是 MIT 俄文版），
  所以**打包分发在法律上没问题**
- 但它的目录里只有 `Everything.exe` + 语言包，**没有 `es.exe`，也没有 SDK DLL**。
  单个 exe 本身不提供可编程查询接口，要么走 IPC（WM_COPYDATA + 共享内存），
  要么靠 es.exe 转发
- 而且 Everything 要在目标机器上以进程/服务形式跑起来才能查

所以「拷一个 Everything.exe 进 exe」并不能让搜索变可用，反而多 2 MB 和一堆进程。
本地索引能把这件事彻底解决，且零依赖、零进程、不联网——这就是我选它的原因。

如果你确实要 100% 复刻 Everything 的体验（NTFS MFT 直读、毫秒级全盘），
那得内嵌 Everything 并实现它的 IPC 协议，工作量不小，可以单独排期。

四个按钮：

| 按钮 | 作用 |
|---|---|
| 载入配置… | 打开现成的 `.yaml` |
| 校验 | 只检查语法，不动文件 |
| 预演 | 显示会发生什么，不动文件 |

### 写规则时的坑

**路径用单引号或正斜杠，不要用双引号。**

```yaml
# ✗ 错：双引号里的 \ 是转义符，会报 "found unknown escape character"
actions:
  - move: "D:\下载\03_文档\"

# ✓ 对
actions:
  - move: 'D:/下载/03_文档/{created.year}/'
```

## 卸载程序（第四个页签）

> ⚠️ **这一页会删除东西**，是本工具唯一会破坏数据的功能。前三页签只移动、不删除，
> 这一页会真的删掉文件和注册表。

参照开源项目 [BCUninstaller](https://github.com/BCUninstaller/Bulk-Crap-Uninstaller)
（Apache-2.0，22k★）的思路**原生实现**，没有内嵌它的 .NET 运行时。

### 功能

| 功能 | 说明 |
|---|---|
| 刷新列表 | 从注册表枚举已安装程序（HKLM 64/32 位 + HKCU），过滤掉系统组件和补丁 |
| 搜索 | 按名称 / 发布者过滤 |
| 普通卸载 | 调用程序自带的卸载器，会弹出它自己的向导 |
| 强制卸载 | 先调自带卸载器，再扫描残留并删除 |

### 强制卸载会删什么

1. **目录**：安装位置、`Program Files\<名称>`、`Program Files (x86)\<名称>`、`ProgramData\<名称>`、`AppData\Local\<名称>`、`AppData\Roaming\<名称>`、`AppData\Local\Programs\<名称>`
2. **注册表**：`HKLM\SOFTWARE\<名称>`、`HKCU\SOFTWARE\<名称>`、以及该程序自己的 `Uninstall\<项>`

删除前会**自动导出 `.reg` 备份**到 `%LOCALAPPDATA%\整理助手\卸载备份\`，
文件名带时间戳，双击即可还原。

### 五道确认

1. 先弹「这一步会先卸载、再扫描、再删除」的说明
2. 列出所有将被删除的目录和注册表项（各最多显示 15 条 + 总数）
3. 第二次 askyesno 确认
4. **要求手动输入「删除」两个字**才执行
5. 删除前导出注册表备份

### 右键菜单（照 Geek Uninstaller 做的）

在程序列表上**右键**任意一行：

| 菜单项 | 行为 |
|---|---|
| 卸载(U) | 调程序自带卸载器（双击列表也是这个） |
| 强制删除并清理残留(F) | 卸载 + 扫残留 + 删除（同上五道确认） |
| 仅删除注册表条目 | 只清注册表，不动文件 |
| 仅删除残留文件 | 只删目录，不动注册表 |
| 打开安装文件夹 | 资源管理器打开 |
| 查看注册表位置 | 打开 regedit 并把键路径写进日志 |
| 备份该程序数据到… | 把安装目录/AppData 复制到你选的位置，注册表导出成 .reg |
| 用 Everything 搜索 | 带着程序名打开 Everything |
| 复制程序信息 | 名称/版本/发布者/路径/卸载命令进剪贴板 |

前四个是**破坏性操作**，都要过「输入删除」那道确认。


### 安全黑名单（硬编码，不可绕过）

| 类型 | 拒绝 |
|---|---|
| 目录 | `C:\`、`Windows`、`System32`、`Program Files` 根、`ProgramData` 根、`Users`、盘符根、层级 ≤ 2 的路径 |
| 注册表 | `SOFTWARE\Microsoft`、`SOFTWARE\Windows`、`SOFTWARE\Classes`、`SOFTWARE\Policies`、`CLSID`、`Run`/`RunOnce` |

只允许删「某个程序自己的 Uninstall 登记项」，不允许删 `Uninstall` 根。

实测 18 条安全用例全部符合预期。

### 管理员权限

清理 `Program Files` 和 `HKLM` 需要管理员。界面右上角会显示当前状态，
未提权时可以点「以管理员身份重启」。不提权也能用，只是这两处会删失败并记日志。

## 递归：三层深度 + 整棵子树放弃

勾选后逐个子目录整理，默认下钻 **3 层**。

一旦某目录被判定为下面三类之一，**它和它底下所有子目录一律不碰**：

| 判定 | 依据 |
|---|---|
| 软件目录 | ≥3 个运行时文件（.dll/.pak/.dat/.asar…），或含 `resources`/`locales`/`plugins` 子目录，或含 `portable.ini`/`icudtl.dat`/`app.asar` 等 |
| 代码工程 | 含 `.git` / `package.json` / `pyproject.toml` / `Cargo.toml` / `node_modules` 等 18 种标志 |
| 源码目录 | 源码文件（.c/.py/.js/.ts/.go/.rs…）达到 5 个 |

另有一份不下钻的目录名清单（`.minecraft`、`mods`、`node_modules`、`存档`、`整合包`、
`备份` 等 76 个），防止把游戏和工程拆散。

## 全盘整理

- 自动跳过 36 个程序/游戏/备份目录（`App`、`Tool`、`pcl2`、`手机备份`、`SteamLibrary` 等）
- `C:\` 根目录永远拒绝

## 安全边界

- 系统目录、`AppData`、盘符根目录、UNC 网络路径、云同步目录一律拒绝
- 快捷方式、系统文件、`.lock`、`~$` 占位、符号链接/联接点不动
- 最近 10 分钟改动过的跳过；被占用的跳过并记录
- 单次超 2000 个文件停止；目标路径超 240 字符跳过
- 永不删除；`overwrite` 也是把旧文件改名备份而非覆盖
- 每次整理留 `_整理记录.txt` 和可撤销的 JSON 历史

## 清理缓存

主界面左侧多了一个 **清理缓存** 页。它扫的是**内置的已知缓存位置**，
不做「全盘找 cache 目录」这种危险操作。

### 能力

- **自动扫描全机缓存**：不需要你一个个找目录，点「扫描缓存」就列出本机所有命中的项，带大小和文件数
- **分三级**：
  | 级别 | 颜色 | 含义 |
  |---|---|---|
  | 安全 | 绿 | 删了只是下次重新生成，不影响使用 |
  | 谨慎 | 橙 | 会丢预览缓存 / 构建缓存，重建会慢一些 |
  | 高级 | 红 | 需要管理员，或涉及系统更新缓存 |
- **清理推荐**：只清「安全」级，一键操作
- **清理选中…**：勾哪清哪，删除前把清单和总大小列给你看
- **添加目录…**：手动加自定义缓存目录（也受同样的安全边界约束）
- **右键菜单**：打开位置 / 复制路径 / 只清理这一项 / 从列表移除
- **每天自动清理**：填时间 → 创建任务，只清「安全」级

### 内置清理项（24 项）

| 分类 | 项 |
|---|---|
| 系统 | 用户临时文件、崩溃转储、错误报告队列、缩略图缓存、回收站、Windows 临时目录*、Windows 更新下载缓存*、传递优化缓存* |
| 浏览器 | Chrome / Edge / Firefox / IE 的 Cache、Code Cache、GPUCache（**不碰书签、密码、Cookie、历史**） |
| 开发 | pip、npm、Yarn、NuGet、Gradle、Maven |
| 应用 | VS Code、Discord、Teams、Slack、Spotify、微信、QQ（只清 Cache 目录） |

带 `*` 的需要管理员权限；没有提权时这些项会失败并写进日志，不影响其他项。

### 边界：什么绝对不碰

这是硬编码在 `CACHE_FORBIDDEN` 里的，**自定义目录也绕不过**：

```
\Windows\System32        \Windows\SysWOW64       \Windows\WinSxS
\Windows\System32\config \Windows\System32\drivers
\Windows\Servicing       \Windows\Assembly       \Windows\Boot
\Windows\Fonts           \Windows\System32\CatRoot
\ProgramData\Microsoft\Crypto
\System Volume Information
用户目录下的 Documents / Desktop / Pictures / Videos / Music / OneDrive / .ssh / .git
```

判定函数是 `cache_path_forbidden()`：命中就拒绝，并在界面上直接告诉你
「它属于系统关键目录 / 个人文件目录，不在可清理范围内」。

另外三条设计原则：

1. **只清内容，不删目录本身**——缓存目录留着，程序下次照常写
2. **被占用的文件自动跳过**，不会硬删导致程序崩
3. **删完自动重扫**，能立刻看到剩余量

### 定时任务

- 任务名：`整理助手_清理缓存`
- 只清「安全」级别 + 你添加的自定义目录
- 日志写到 `数据\缓存清理.log`

## 关于「删了会不会坏」

缓存的本质是**可以重新生成的中间产物**：

- 浏览器缓存删了 → 网页第一次打开慢一点，之后自动重建
- 临时文件删了 → 没有影响，本来重启也会清
- 缩略图删了 → 资源管理器重新生成
- 回收站清空 → 这个真的没了，所以它被标成「谨慎」且默认不勾

真正会出问题的是删 **程序安装目录、系统目录、用户文档**——这三类在
本工具里被硬性排除，无论怎么点都不会动。

## 三条硬边界（怎么点都不会破）

1. **系统关键目录**：`Windows\System32`、`WinSxS`、`servicing`、`Fonts`、
   `Crypto`、`System Volume Information` 等，代码里是常量黑名单，直接拒绝。
2. **个人文件目录**：`Documents`、`Desktop`、`Pictures`、`Videos`、`Music`、
   `OneDrive`、`.ssh`、`.git` —— 无论清单里怎么写，都过不了校验。
3. **回收站**单独处理，标「谨慎」，默认不勾。

「清理推荐」按钮只清 **安全（绿色）** 这一级，谨慎和高级永远要你自己手动勾。
每天自动清理的计划任务，同样只清安全级。
