# 整理助手 UI 规范：加载、占位与反馈系统

> 配套：`UI重设计_设计规范.md`（令牌与组件底座）、`UI重设计_逐页方案.md`（每页布局）。
> 本文把 7 类加载/反馈组件、6 组交互动效关键词、出现/过渡/消失三态与防闪烁阈值，落成可实现的规则。
> 关键前提：目标是 **Windows 桌面原生（WPF）**，不是网页；「全屏 Page Loader」「Skeleton」「Shimmer」等概念按桌面语境改写，移动端手势类关键词（长按透视浮起、卡片堆叠滑动）只在触屏场景成立，桌面版给出等价或有理由的取舍。

---

## 0 原则（比组件更重要）

1. **不假加载**。任何加载态只表达真实等待：有进度就显示进度，没有就老实显示不确定态；不为了「看起来高级」而加延迟动画。
2. **300 ms 防闪烁**：任何加载态只在等待超过 300 ms 后出现；内容在 300 ms 内到达则直接显示，不经过 loading（否则会出现一闪而过的骨架/转圈）。
3. **8 秒给出口**：任何超过 8 秒仍未完成的操作，必须出现「取消 / 重试」与一句原因（正在枚举注册表 / 正在读取 10 万文件 / 引擎无响应）；不允许无限转圈。
4. **禁止提前交互**：加载中的区域必须 `IsHitTestVisible=false` 并移出 Tab 序列；按钮进入禁用态；不允许用户在「看起来已就绪」的界面上操作空数据。
5. **三态齐全**：每个会变化的元素都要有出现动画、过渡动画、消失动画；无动画 = 状态切换生硬，视为缺陷（`prefers-reduced-motion` / Windows「动画效果」关闭时降级为纯淡入淡出）。
6. **不跳动**：骨架与真实内容占位尺寸一致（行高 32、分组行 36、卡片高固定），内容替换用交叉淡入，绝不因加载完成改变布局。
7. **不抢焦点**：加载态不移动键盘焦点；完成后焦点回到触发操作的元素。
8. **颜色纪律**：白/灰为底，加载态只用中性灰 + 一个强调色；红色只用于失败，绿色只用于完成。

## 1 选型判定树

```
操作触发
├─ 预计 <300ms ───────────────────────────────→ 无加载态，直接切换
├─ 首屏/整页内容未知且预计 0.6~5s ────────────→ Page Loader（整区遮罩）
├─ 页面结构已知、只缺数据（列表/卡片）────────→ Skeleton（+Shimmer 若 >300ms）
├─ 后台任务、ETA 未知、不允许离开 ────────────→ Spinner + 「处理中 请勿关闭」+ 8s 出口
├─ 可量化进度（扫描/导出/迁移/索引）──────────→ Progress Bar（阶段 + 百分比）
├─ 紧凑位置（按钮旁/卡片角/指标）─────────────→ Circular Progress（40px，带百分比）
└─ 触发者是按钮本身（保存/校验/执行/开始）────→ Button Loader（原位变形，不换布局）
```

禁止：同一区域同时出现 Spinner 与 Skeleton；同一页面同时出现 Page Loader 与按钮加载态（按钮态保留，遮罩取消）。

## 2 组件规范

### 2.1 Page Loader（整页加载遮罩）

| 项 | 规格 |
|---|---|
| 用途 | 首次打开程序（引擎预热）、首次进入某页需要长时间准备（索引库迁移、卸载列表首次枚举） |
| 时长预期 | 0.6–5 s；>8 s 转 Spinner 的出口逻辑 |
| 视觉 | 内容区（不含左栏与状态栏）覆盖 `#FFFFFF` 92% 不透明层；中央：产品图标 32 + 2 px 环形不确定进度（24 px）+ 文案「正在初始化…」T3 13；下方 1 行灰色小字说明当前步骤（「正在加载规则」「正在准备引擎」） |
| 出现 | 立即出现（不做延迟），透明 0→1，140 ms；图标轻微 scale 0.96→1 |
| 过渡 | 步骤文案变化用 120 ms 淡入淡出；环形旋转 900 ms/圈 |
| 消失 | 内容就绪后：遮罩 200 ms 淡出 + 内容 200 ms 淡入（交叉），先解锁交互再淡出，避免「看得见点不到」 |
| 禁止 | 遮罩内不放按钮（除 8 s 后的「取消 / 重试」）；不能用它替代可预期的骨架 |
| 可访问性 | `AutomationProperties.LiveSetting=Polite` 播报「正在加载」；关闭动画时只保留文字变化 |
| 错误 | 失败则遮罩换成错误态：图标 + 一句原因 + 「重试」「查看日志」 |

### 2.2 Skeleton（骨架屏）

| 项 | 规格 |
|---|---|
| 用途 | 页面结构已知、数据未到：清理缓存 6 组、卸载列表、搜索结果、截图列表、整理预览树、设置页 5 组 |
| 视觉 | 占位块 `#F2F3F5`，圆角 4；行高与真实行一致（32 / 分组 36 / 卡片按真实高度）；宽度按列宽比例，末端留 10% 随机感但每次相同（不随机，避免抖动） |
| 布局 | 必须复刻真实布局：标题条、列头、行、右对齐数值块、勾选列都以灰块存在 |
| 出现 | 延迟 120 ms 出现（300 ms 规则的前置），避免一闪 |
| 过渡 | 数据到达：骨架 160 ms 淡出、内容 160 ms 淡入 + 整体 4 px 上移；同位置替换，不重排 |
| 消失 | 与内容交叉完成；超过 8 s 仍在等 → 顶部 InfoBar「加载较慢」+「重试」 |
| 可访问性 | 骨架对屏幕阅读器隐藏（`AutomationProperties.IsOffscreenBehavior` 或直接 `Visibility` 控制），只播报一次「正在加载 N 项」 |

### 2.3 Skeleton + Shimmer（扫光）

| 项 | 规格 |
|---|---|
| 用途 | 仅在 Skeleton 已显示且加载 >300 ms 时启用；用完即关 |
| 视觉 | 线性渐变扫光：`#F2F3F5 → #FFFFFF 40% → #F2F3F5`，带宽 30% 骨架宽度，透明度峰值 0.9；从左到右 1.2 s 一轮，循环 |
| 实现 | WPF：`LinearGradientBrush` 的 `Offset` 用 `DoubleAnimation` 平移（`RenderTransform`），无第三方库；动画跑在 Composition 线程友好属性上（`TranslateTransform`） |
| 出现/消失 | 与 Skeleton 同时淡入（+0 ms）；内容到达立即停止并 120 ms 淡出，不做「扫到一半暂停」 |
| 节能 | 窗口失焦或最小化时暂停（`IsVisibleChanged` 停动画） |
| 降级 | 系统关闭动画 → 静态骨架，不扫光 |

### 2.4 Spinner（任务区转圈）

| 项 | 规格 |
|---|---|
| 用途 | ETA 未知、不可量化的后台任务（卸载注册表枚举、强制卸载扫描残留、规则执行） |
| 视觉 | 24 px 圆环，2 px 描边，`Line #E6E8EB` 底 + `Accent` 弧 90°，900 ms/圈，线性；下方「处理中，请勿关闭」T3 13，再下行灰色小字说明在做什么 |
| 位置 | 任务区中央（不是整窗）；不遮挡状态栏 |
| 出现 | 300 ms 延迟 |
| 过渡 | 任务阶段变化只换副文案，120 ms 淡入淡出；转圈不加速/减速（会让人误判进度） |
| 消失 | 完成：160 ms 淡出 → 结果提示（成功 InfoBar 或结果核对框）；失败：换成错误态 + 「重试」「查看日志」 |
| 8 s | 出现「取消」次级按钮与「还在处理，可能较慢」提示；取消需 1 次确认（正在写入时提示风险） |
| 可访问性 | 播报「处理中」；`IsHitTestVisible` 保持可用（取消按钮必须可点），但任务区其他控件禁用 |

### 2.5 Progress Bar（带百分比）

| 项 | 规格 |
|---|---|
| 用途 | 可量化：扫描预览、导出 CSV、迁移、索引构建、缓存清理、截图清理 |
| 视觉 | 高 4 px，圆角 2，底 `#EEF0F3`，填充 `Accent`；上方一行「正在扫描 D:\下载 · 1,204/1,940 个文件 · 62%」T4 12；阶段名 T3 13 |
| 位置 | 状态栏（跨页常驻）或页面进度区（数据迁移页底部 64 px） |
| 过渡 | 数值平滑跟随（200 ms 插值），不跳变；阶段切换时百分比短暂停顿并淡入新阶段名 |
| 完成 | 100% 后进度条 180 ms 变为 `Success` 实心并保持 1 s，下方出现主按钮「完成 / 查看结果 / 打开目录」，2 s 后自动回到就绪态（按钮消失） |
| 取消 | 进度区右侧「取消」；取消后保留已完成计数并报告 |
| 不确定态 | 用 marquee（与系统一致），不显示假百分比；结论同 Spinner |

### 2.6 Circular Progress（环形进度圈）

| 项 | 规格 |
|---|---|
| 用途 | 空间紧凑处：按钮右侧、卡片角、指标旁（索引构建、批量任务里的小进度） |
| 视觉 | 40 px（小号 24 px），3 px 描边，中心 11 px 数字；底 `#EEF0F3`，弧色随进度：0–60% `Accent`，60–99% `Accent` 保持，100% `Success`；仅「停滞告警」时用 `Danger` |
| 动效 | 弧长 200 ms 缓动跟随；数字变化只做透明度 80 ms；完成时 300 ms 打勾动画（路径描边） |
| 位置 | 与文案基线对齐，不进入表格列（表格内用纯文字百分比） |
| 降级 | 关闭动画：直接跳到目标值 |

### 2.7 Button Loader（按钮内加载）

| 项 | 规格 |
|---|---|
| 用途 | 保存设置、校验/预演/执行规则、开始整理、开始迁移、卸载、重建索引 |
| 视觉 | 按钮宽度锁定（内容区放 14 px Spinner + 「保存中…」），按钮底色淡化到 60%，文字保持可读；不改变按钮尺寸与周围布局 |
| 出现 | 点击立即进入（按钮触发的等待必须即时反馈），不套 300 ms 延迟 |
| 过渡 | 文案与 Spinner 用 120 ms 淡入；成功后 200 ms 换回原文案 + 短暂 `Success` 勾 1 s；失败改为「重试」按钮（同尺寸、Danger 描边） |
| 禁止 | 不禁用整个页面，只禁用该按钮与被它影响的最小区域（如保存时禁用同组输入） |
| 键盘 | 加载中保持焦点在按钮上，Enter 不重复提交（禁用态吞掉按键） |
| 8 s | 按钮旁出现次级「取消」文字按钮；仍不可重复点击 |

## 3 阈值与时序总表

| 时机 | 规则 |
|---|---|
| 0 ms | 按钮加载态、进度条、取消可用；点击必须有即时视觉反馈（按下缩到 0.98、80 ms 回弹） |
| 120 ms | Skeleton 出现 |
| 300 ms | Spinner / Page Loader 说明页 / Shimmer 开始；未超过 300 ms 的等待不显示任何加载态 |
| 1 000 ms | 长任务补一句「正在做什么」（防用户以为卡死） |
| 8 000 ms | 出现「取消 / 重试」+ 原因说明；不再转圈无出口 |
| 完成 | 交叉淡入 160–200 ms；按钮态 / 进度条 1–2 s 后回到就绪 |

所有阈值集中在一个 `LoadingPolicy` 常量类（WPF `static class`），不在各页面散写。

## 4 六组交互动效关键词的落地

> 用户给的是移动端手势语言。桌面版逐条判断：能成立就实现，不成立就说明取舍并给等价方案，不硬套。

| # | 关键词 | 桌面可行性 | 本产品落点 |
|---|---|---|---|
| 1 | 面板分层浮起（长按/透视/X 轴旋转/Z 位移/多层分离/弹簧/松手合拢） | 部分可行，但「长按看透视」在鼠标上是反效率操作 | 改用于**命令面板（Ctrl+K）与侧抽屉**：浮层从内容区顶部 8 px、scale 0.98→1、阴影 0→8 分层出现，关闭反向 120 ms；不使用 3D 旋转（与工具型克制风格冲突） |
| 2 | 堆叠滑动切换（卡片堆叠/拖拽/阈值甩出/回弹/底层上移缩放） | 桌面无「卡片堆叠」场景；文件不按卡片流转 | 取舍：不实现。等价的「堆叠」用于**预览侧抽屉与多窗口任务历史**：任务历史卡片纵向堆叠，选中项上浮 2 px、阴影加深 |
| 3 | 多选聚成一叠（长按多选/勾选/聚合/飞向手指/错帧/堆叠/数量角标/拖拽批量） | 「飞向手指」无意义，但「聚合 + 数量角标」成立 | 用于**批量操作浮出条**：勾选时被选行同时轻微高亮（背景 `SurfaceSelected`），浮出条从底部 12 px 处 160 ms 升起，计数用错帧数字滚动（每 40 ms 一位）；拖拽批量移到回收站保留原生拖放光标 |
| 4 | 按钮一分为二（中线分裂/间隙撑开/状态切换/合并复原） | 可行但属于「炫技型」动效，违背工具型克制 | 取舍：仅在**开始整理/开始迁移**用简化版：点击后主按钮从中间撑开为「暂停 / 继续」两个（各 120 ms 宽度动画），完成后合并回单按钮。默认关闭，设置里可开（低优先级，待确认） |
| 5 | 滚动变小窗（滚动触发/画中画/位置迁移/角落吸附/点击还原） | 可行 | 用于**监控模式与正在运行的迁移**：滚动离开任务区时，任务进度收成右下角 240×56 的浮动小窗（进度条 + 取消），点击回到任务区原位；仅在长任务进行中显示 |
| 6 | 分类联动滚动（左右联动/scroll-spy/锚点/平滑滚动） | 完全可行且对本产品有用 | 用于**清理缓存页（左侧 6 组锚点 + 右侧列表联动）**与**设置页（左侧分组索引 + 滚动高亮）**：滚动时左侧锚点高亮跟随（scroll-spy，80 ms 过渡），点击锚点平滑滚动到组（240 ms landing，系统关闭动画时直达） |

## 5 无缝衔接与 Morph

WPF 没有内置 shared-element transition，但「无缝」不靠炫技，靠三条：

1. **零跳动**：骨架尺寸 = 真实尺寸；加载完成只做交叉淡入 + ≤8 px 位移；列表不重新排序（数据到达后保持稳定排序）。
2. **形变替代**：能用一个元素变形完成的状态切换，绝不换成两个元素。已确定的形变点：
   - 搜索框聚焦：高 32→40（scaleY 1→1.25，锚点底部），图标 16→18；
   - 设置项保存：行尾「已保存」从 0 宽展开（120 ms）再淡出；
   - 数据目录变更：底部「配置文件：…」标签 200 ms 淡出 → 新路径淡入，同时数据目录行右侧出现「已迁移 / 仅保存」徽标；
   - 主按钮 → Button Loader → 成功：宽度锁定，三态同框，不换控件；
   - 整理预览 → 开始整理：命令栏主按钮从「扫描预览」形变为「开始整理」（文字 120 ms 交叉淡入，按钮宽度 160 ms 过渡）；
   - 清理缓存「扫描」→「清理推荐」：同一按钮位置，文字与图标同步淡入，禁则：不同时出现两个实心按钮。
3. **空间连续**：跨页保留滚动位置与选中行；主从切换（卸载列表 → 详情、搜索 → 侧抽屉预览）时，选中行缩放到详情面板位置（可用 160 ms 位移 + 180 ms 交叉淡入近似，不做真实 rect 插值——WPF 手写成本高且易卡顿）。

实现方式：`VisualStateManager` + `Storyboard`；复杂共享元素（行→详情）用 `RenderTransform` 的平移/缩放 + 交叉淡入，避免 `LayoutTransform` 引发布局重排。

## 6 页面 × 加载态矩阵

| 页面 | 首次进入 | 主要加载态 | 占位区域 | 完成衔接 | 空态 | 失败态 |
|---|---|---|---|---|---|---|
| 整理文件 | Page Loader（引擎预热，<5 s） | 扫描：底部 Progress Bar + 列表 Skeleton；监控触发：Spinner 不遮挡页面 | 分类树区域（6 行分组骨架） | 100% → 「完成 · 撤销」按钮 2 s 后归位 | 拖入文件夹的虚线区 + 主按钮 | InfoBar「扫描失败」+ 重试 |
| 清理截图 | 无（数据本地快） | 扫描：Progress Bar；清理：Button Loader | 列表 8 行骨架 | 清理完成 InfoBar「已清理 12 张 回收站可还原」 | 「没有识别到截图」+ 管理目录入口 | InfoBar + 重试 |
| 清理缓存 | 无 | 扫描：Progress Bar（按项）+ 分组骨架 | 6 组 × 1 行分组骨架 | 清理后自动重扫，进度条走第二遍 | 「全部干净」空态 | 单行失败标记 + 汇总 InfoBar |
| 高级规则 | 无（YAML 即时） | 校验/预演/执行：Button Loader | 无（不骨架化编辑器） | 输出面板逐行追加 | 模板提示 | 行内波浪线 + 底部错误定位 |
| 卸载程序 | Page Loader（首次枚举注册表 1–3 s） | 刷新：Progress Bar（枚举中）；卸载/强制卸载：Spinner「处理中 请勿关闭」 | 表格 12 行骨架 + 详情 4 行骨架 | 完成后刷新列表并高亮该行 1 s | 「没有匹配的程序」 | Spinner 8 s → 取消/重试 + 原因 |
| 搜索文件 | 无 | 建索引：Progress Bar（百分比 + 阶段）；搜索：输入框内 12 px Spinner | 结果 8 行骨架（首次搜索） | 结果整块淡入，耗时显示在状态栏 | 未建索引引导 / 无结果建议 | InfoBar「索引不可用」+ 重建 |
| 设置 | Page Loader（读配置 <0.6 s 时可省） | 保存：Button Loader；迁移：Progress Bar + 右下浮动小窗 | 5 组卡片骨架（数据目录行） | 「已保存」行尾展开 1.5 s | 无 | 行内红字 + 控件回退 |
| 数据迁移 | 无 | 预览：Progress Bar（不确定→确定）；执行：Progress Bar + 取消；撤销：Button Loader | 总览表 6 行骨架 | 完成：进度区显示「完成 N / 跳过 N / 失败 N」+ 导出报告 | 「先添加来源」空态 | 失败行可展开原因 + 重试 |

## 7 当前 Tkinter 版本能先落地的子集

若不等待原生版、希望在 b4 上就改善加载体验，按性价比排序：

1. **Button Loader**（最高）：保存/扫描/清理/执行按钮点击后禁用 + 文案改「处理中…」+ 边框变灰；改动小、收益直接。
2. **底部 Progress Bar 加百分比与阶段**：现有 `bar_holder` 与 `run_task` 已具备进度通道，只需补文字与 100% 完成提示。
3. **Skeleton（静态灰条）**：Tk `Frame` 灰块按真实行高铺 6~12 行，数据到达后销毁并填表；不需要动画也明显改善「白屏感」。
4. **Page Loader**：`Toplevel` 无边框半透明遮罩 + Canvas 转圈，首次启动显示；注意 Tk 无真正的半透明混合，只能用 95% 白底遮挡，观感略糙。
5. **Shimmer**：Canvas 上跑渐变条的 `after(16ms)` 重绘，CPU 开销与闪烁风险高，**不建议**在 Tk 版做，留到 WPF。
6. **Circular Progress**：Canvas `create_arc` 可做，但表格内用途有限，优先级最低。

结论：b4 若要小改，只做 1+2；3 视情况；4~6 留给原生版。

## 8 验收清单（加载与反馈）

- [ ] 300 ms 内完成的加载不出现任何 loading 视觉（逐页录像验证）
- [ ] Skeleton 与真实内容行高一致，替换瞬间列表高度不变（截图像素对比）
- [ ] Shimmer 只在 loading 期间存在，内容出现后 120 ms 内完全消失，窗口失焦时暂停
- [ ] Spinner 超过 8 s 一定出现「取消 / 重试」与原因
- [ ] Progress Bar 到达 100% 后出现完成按钮，2 s 后回到就绪态
- [ ] Circular Progress 完成后打勾、颜色变绿，不出现红色（除停滞告警）
- [ ] Button Loader 期间按钮尺寸不变、不可重复提交、失败变「重试」
- [ ] 每个页面有出现/过渡/消失三态；切换页面 160 ms 交叉淡入，无白闪
- [ ] 系统关闭动画时，全部降级为淡入淡出且功能不受影响
- [ ] 屏幕阅读器播报「正在加载 / 处理中 / 已完成」，骨架不逐个朗读
- [ ] 加载期间 Tab 不能进入被遮罩区域；完成后焦点回到触发元素
