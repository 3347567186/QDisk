# 数据迁移 —— 设计与实现

给整理助手加的「搬家」能力：把文件、文件夹、应用数据目录、压缩包整棵搬到另一个位置。
默认只预演，动手前先体检；执行时边搬边记账，崩了能接着跑，搬完能回滚。

实现：`migrate_engine.py`（约 1200 行，零第三方依赖）+ `tidy.py` 的「数据迁移」页与 `--migrate` 命令。

---

## 1. 目标与边界

**做**：同卷/跨卷移动与复制；整目录树；链接按原样搬；重名四种策略；字节级校验；
断点续跑；整体回滚；迁移报告。

**不做**（明确留白，避免「看起来支持其实半吊子」）：
ACL/所有者/审计信息、备用数据流（Zone.Identifier）、EFS 加密、稀疏文件、
ReFS 块克隆、影子副本（VSS）。需要这些时用 robocopy `/COPYALL` 单独处理，
本文第 10 节说明为什么不做。

---

## 2. 参考了哪些现成实现

| 参考 | 拿走的做法 | 没照搬的原因 |
|---|---|---|
| **robocopy**（Windows 内置） | `/Z` 可续传、`/B` 备份模式、`/XJ` 不跟 junction、`/COPY:DAT`、`/DCOPY:T`、`/LFSM` 低空间暂停、退出码语义 | `/MOVE` 是「复制一个删一个」，不写事务日志，崩在中途没法解释状态；`/MT` 与 `/LFSM` 互斥 |
| **rclone** | 临时名 + 原子 rename（`--partial-suffix`）、`--dry-run`、`--checksum`、`--backup-dir`、源目标重叠直接报错、`--delete-empty-src-dirs` | 面向云存储，元数据模型和 Windows 链接语义不同 |
| **rsync** | `--dry-run`/`--itemize-changes` 的可解释输出、`--delay-updates` 最后统一改名 | 依赖服务端协议；Windows 上没有可靠端口 |
| **FastCopy / TeraCopy** | 「复制 + 校验」双阶段、校验失败保留源、操作可撤销 | 闭源；其 UI 交互不可复用 |
| **PowerToys File Locksmith** | 用 **Restart Manager**（`RmStartSession/RmRegisterResources/RmGetList`）查占用进程，而不是靠「尝试独占打开」猜 | — |
| **CPython `shutil.move`** | —— | 跨卷时是 `copytree` + `rmtree`，不校验、不原子、链接会被展开；2026-10 那次迁移事故就是这类语义造成的 |
| **python-dotenv CVE-2025-…（GHSA-mf9w-mj56-hr94）** | 反面教材：跨设备 rename 回退时跟随符号链接 → 任意文件覆盖 | 本引擎对链接 `lstat` 判定，永不跟随 |

## 3. 五段式流程

```
build_plan()        扫描 → 逐项清单（src, dst, kind, size, mtime, action）
   ↓                只读，不动任何文件
preflight()         空间/同卷/嵌套/长路径/保留名/链接/占用/大小写重名
   ↓                error 级问题直接拦下
execute()           建目录 → 逐项搬 → 每步写日志 → 校验 → 删源
   ↓
verify_job()        事后复核：目标在不在、大小哈希对不对
undo_job()          按日志逆序搬回，恢复被覆盖的备份
```

清单是**可序列化**的（`plan.json`），所以「先看后做」「中断后续跑」「事后审计」
用的是同一份事实，不存在「预览一套、执行另一套」。

---

## 4. 七条安全不变量

1. **源文件只在目标校验通过、且日志已落盘之后才删除。**
   顺序固定为 `复制到临时名 → fsync → 校验 → os.replace → 写日志 → 删源`。
2. **同卷移动只做 `os.rename`。** 原子、瞬时、零拷贝；失败也不会留下半份数据。
3. **永不覆盖。** 重名默认改名；要覆盖必须显式选「覆盖」，且旧目标先挪进
   `<任务目录>/backup/`，回滚时原样放回。
4. **永不跟随链接。** junction / 符号链接作为「链接本身」处理：同卷直接改名，
   跨卷用 `mklink /J` 重建；重建不了就报错，绝不悄悄展开成一份拷贝。
5. **永不搬自己。** 目标是源的子目录、源是目标的子目录、整盘根、系统目录、
   用户目录根，预检直接拒绝。
6. **取消只发生在文件边界。** 正在复制的文件会删掉临时文件、保留源；
   已完成的项都已校验落盘，界面明确告知停在哪。
7. **回滚只动自己搬过的东西。** 目标内容哈希变了就不动它，列出来让人判断。

## 5. 状态机与崩溃恢复

每项状态：`pending → done / skipped / failed`，状态变更写进 `journal.db`（SQLite WAL）。

关键顺序：

```
copy → fsync → verify → os.replace → journal(commit, flush) → delete source
```

- 崩在 `copy` 阶段：临时文件是 `.~mig-<iid>.tmp`，重跑时先清掉再复制，源完好。
- 崩在 `replace` 之后、删源之前：重跑发现目标已存在且校验通过 → 补删源。
- 崩在删源之后：状态已是 `done`，重跑跳过。
- 并发下日志用一把锁串行化，每 50 条批量提交；涉及「发布」和「删源」的节点强制立即提交。

`--resume <任务号>` 或界面上的续跑，会从 `plan.json` + 日志恢复，不会重复搬已完成项。

## 6. 两条执行路径

| 条件 | 做法 | 复杂度 |
|---|---|---|
| 同卷 + 移动 + 不跟随链接 | `os.rename(src, dst)`，一次系统调用 | O(1)，18 万文件也是秒级 |
| 跨卷，或复制，或跟随链接 | 逐文件：临时名写入 → `FlushFileBuffers` → 回读校验 → 原子改名 | O(bytes) |
| 链接跨卷 | `mklink /J` 重建（junction 不需要管理员） | O(1) |

同卷判定用 `os.lstat().st_dev`（Windows 上是卷序列号），**用 lstat 而不是 stat**：
junction 必须按「链接自己所在的卷」算，否则会把跨卷链接误判成同卷，`rename` 报 WinError 17。
这个坑在演练时真实踩到过。

---

## 7. 冲突策略

| 策略 | 行为 | 适用 |
|---|---|---|
| `rename`（默认） | `报告 (2).docx` | 通用，最安全 |
| `skip` | 保留目标，源不动，记 `skipped` | 只补缺失 |
| `overwrite` | 旧目标移入任务备份区，再放新的 | 明确要覆盖 |
| `merge` | 目录逐文件合并，文件仍按 `rename` | 合并两棵树 |
| `newer` | 目标更新则跳过 | 增量同步 |

计划阶段先解析一次，执行时若目标被别的进程抢先创建，再按同一策略处理一次。

---

## 8. 校验策略

| 模式 | 做法 | 成本 |
|---|---|---|
| `auto`（默认） | ≤128 MB 全量 BLAKE2b-128（复制时顺带算源哈希，落盘后回读目标再算一遍）；>128 MB 取首尾各 1 MB 抽样 | 小文件近似零成本，大文件只多读 2 MB |
| `hash` | 全量哈希，最大确定性 | 读两遍 |
| `size` | 只比大小 | 最低 |
| `none` | 不校验（同卷 rename 时本来也不需要） | — |

复制开始前和结束后各 `stat` 一次源文件；大小或 mtime 变了说明「复制过程中被改写」，
直接放弃这一项并保留源。

---

## 9. 并发与性能

- `ThreadPoolExecutor`，默认 4 路（SSD 上小文件受益，机械盘建议 1–2）。
- 4 MB 缓冲、无 Python 层逐字节处理；顺序读 + 顺序写。
- 目录先统一建好，失败的文件不会留下半棵树。
- 预览只渲染前 3000 行，计划本身不受限（大目录不会把界面卡死）。
- 同卷移动不读盘：8 万文件的目录搬家是「改名」而不是「复制」。

---

## 10. 为什么不做 ACL / ADS / 稀疏

这些需要 `CopyFile2` 或 robocopy `/COPYALL` 级别的控制，Python 标准库覆盖不到，
硬做的结果是「有的文件属性丢了、有的没丢」，比明确不支持更危险。
需要完整元数据时：本引擎负责规划、校验、日志、回滚，实际复制交给
`robocopy /E /COPYALL /DCOPY:DAT /XJ /R:2 /W:2`，再把结果并回日志。
后续版本可以加 `engine="robocopy"` 的适配层。

## 11. 界面与命令

**界面**：左侧「数据迁移」页

1. 添加文件夹 / 文件（可多个）
2. 选目标目录
3. 选项：移动/复制、重名策略、校验级别、是否保留来源文件夹名、删源进回收站、并发
4. **预演** → 表格列出每一项「来源 → 目标」，阻断项红字列出
5. **开始迁移** → 二次确认 → 底部进度条 + 每行状态
6. **取消** / **撤销上次** / **任务历史** / **导出报告**

**任务历史**：列出每次迁移的时间、方式、目标、完成/失败数、状态、任务号；选中任意一行
可以「回滚选中」或「复核选中」（重新比对大小与哈希），也能直接打开任务目录看
`plan.json` / `journal.db` / 备份文件。

选项（方式、重名策略、校验级别、是否保留文件夹名、是否进回收站、并发、上次的目标目录）
写进 `settings.json` 的 `migrate` 段，下次打开沿用上次的选择。

`TIDY_TAB=7` 可直接从迁移页启动。

**命令**（`整理助手.exe --migrate ...` 或 `python tidy.py --migrate ...`）：

```powershell
整理助手.exe --migrate --to E:\归档 D:\下载            # 预演
整理助手.exe --migrate --to E:\归档 --apply D:\下载    # 执行
整理助手.exe --migrate --to E:\归档 --copy --conflict skip --verify hash --apply D:\下载
整理助手.exe --migrate --list                          # 任务列表
整理助手.exe --migrate --undo 20261028-101500-ab12cd   # 回滚
整理助手.exe --migrate --resume 20261028-101500-ab12cd # 续跑
```

退出码：0 成功 / 1 有失败或阻断 / 2 参数不全。

## 13. 已知限制

- 需要 `migrate_engine.py` 与 `tidy.py` 同目录；打包时 PyInstaller 会自动收进去，
  但**必须重新构建 exe**，旧的 47 MB exe 里没有这个模块。
- 目标盘若是网络盘/移动盘，「删源进回收站」可能失败，会自动退回直接删除并记录。
- 大于 128 MB 的文件默认抽样校验；要绝对确定就选「全量哈希」。
- 被独占锁定的文件会失败并列出；预检阶段用 Restart Manager 提示占用进程名。
- 长路径依赖程序清单里的 longPathAware；引擎已加 `\\?\` 兜底。
