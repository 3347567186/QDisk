# AI 助手方案（第二版：内嵌轻量 Agent）

状态：**已实现**（v1.21 起上线；本文同时是当前行为说明）。环路由 `src\web\js\ai\agent.js` 承担，
改行为请同步改 §十三 的黄金集。
第一版（v1，单次批量分析）已被本版取代；两版差异见文末「附录 A」。

定位：把「问一句就能查清这个文件/这个目录」做进软件，**模型只负责选工具和解释，
所有文件操作仍然由现有引擎执行、由用户点击确认**。

---

## 一、先讲清楚：这版为什么长这样

设计前查了当前（2025–2026）在做「小型内嵌 agent」的公开实践，其中可复用的 7 条规律
与本方案的对应关系如下。**每条都对应下面某一节的具体设计**，不是泛泛引用。

| # | 外部实践中的结论 | 本方案怎么落地 |
|---|---|---|
| 1 | 小模型不是「缩小的大模型」：它的优势在**窄工具面 + 强约束输出**。一个 350M 模型在 ToolBench 上微调后 pass rate 77.55%，超过 GPT-4-CoT 的 26%，原因正是「参数全用在工具调用上」 | 工具面固定 8 个、全部只读；输出强制 JSON；不做开放式对话（§4、§7） |
| 2 | 本地/小模型跑 agent 的关键是**运行时架构**而不是 prompt：稳定前缀（KV cache 复用）、语法约束解码（GBNF）、有界 prompt 尾部、状态外置 | prompt 分「稳定段 + 变化段」；默认取 OpenAI 兼容的 `response_format`/JSON 语法；状态（会话、事实缓存）全在磁盘不在模型里（§5、§6、§9） |
| 3 | 工具数一多，选择准确率会塌（语义混淆，超过约 60 个工具时明显下降）；能自适应地少给工具反而更准 | 8 个工具，且**按页面上下文只启用相关子集**（空间工具页给 4 个，整理页给 5 个）（§4） |
| 4 | 长会话必须分级压缩：软裁剪旧工具结果 → 硬裁剪 → 摘要压缩，且要保护最近若干轮 | 三档预算 + 最近 3 轮原文保护，见 §6 的阈值表 |
| 5 | 破坏性动作要靠**能力隔离 + 审批门**，而不是靠提示词劝阻；审批要绑定具体参数、按可逆性分级，否则会「确认疲劳」 | 工具表里根本没有写操作；AI 只能产出「建议动作卡」，点了走的是原有确认弹窗（§10） |
| 6 | 可测性要一开始就设计：结构合法率、工具选择准确率、每成功任务成本是可运营指标 | 提供脚本化假模型 + 28 条黄金集的离线自检，指标写死在下限（§13） |
| 7 | 桌面端嵌入形态优先「单进程内 + 状态外置」，加一个 sidecar 进程的代价只在需要隔离/跨端复用时才值得 | 不新增进程；HTTP 走 Rust 一条命令，环路在前端（§3） |

参考来源见 §17。

## 二、要解决的 5 类真实提问

不再是 v1 的「一次性给 20 个文件打分」，而是用户真的会打出来的话：

1. **这是什么**：「`vmdk` 这 3 个文件是哪个虚拟机的」「`cache` 目录是谁在用」
2. **能不能删**：「这 4 个能删吗」「删了会不会影响某个软件」
3. **怎么整理**：「这堆下载文件怎么分」「为什么这个 pdf 被分到 03_文档」
4. **在哪**：「我上个月那个 3 GB 的安装包去哪了」
5. **出了什么事**：「为什么这次只整理了 3 个文件」「撤销为什么找不到上次记录」

第 4、5 类今天的软件完全答不了（搜索要索引、日志要人读），这正是内嵌 agent 的价值。

## 三、形态：环路放前端，HTTP 放 Rust

三个方案对比（这是本方案最关键的工程决策，写清理由）：

| 方案 | 做法 | 优点 | 致命问题 | 结论 |
|---|---|---|---|---|
| A 环路放 Python 引擎 | 新增 `ai.chat` RPC，引擎内跑循环 | 一处实现、可 headless 测 | 引擎是**单线程 stdin/stdout**：`call_raw` 只读一行（`main.rs:242-251`），跑起来期间不能取消、不能流式、不能进度；`_engine_progress` 在引擎模式下被显式吞掉（`tidy.py:10718`） | 放弃 |
| B 独立 sidecar 进程 | 仿 atomic-agent，NDJSON sidecar | 隔离干净、可复用 | 多一个进程、多一套生命周期/打包/签名，本软件只有单窗口 | 过度设计 |
| **C 环路在前端 + HTTP 在 Rust** | 每步一次 `ai_http`（Rust 发一次 HTTP）+ 一次工具调用（现有 invoke），循环在 JS | 取消=丢结果；进度天然按步渲染；无 CORS 限制；密钥不在页面 JS 里拼 URL；不改引擎协议 | 循环逻辑在 JS，需要单独的可测设计 | **采用** |

C 的关键点：

- **单步 = 一次模型调用**，最长 20 s；整轮步数上限 6 步，最坏 2 min，全程可取消。
- 取消分两层：前端置旗标让环路立刻停（`Promise.race` 直接结束在飞的那次 await），
  Rust 侧 `ai_cancel` 置全局旗标，读响应的循环每个分片检查一次并断开连接。
  只做前者会白烧这一轮的 token，只做后者界面还要等网络反应，所以两层都要。
- 停下不丢进度：`run()` 每次都把 `{messages, steps, trace, calledTools, compressed}` 存成
  checkpoint 随结果返回，界面给「继续」按钮，下次 `run({resume})` 从断点接着跑，
  已经查过的工具不重查（重查一次就是重发一次整段 prompt）。
- **一步最多 3 个互不依赖的只读工具**：`{"tools":[...]}` 这种形状，执行仍串行，
  省的是模型往返和整段重发；有依赖的查询必须等上一步结果。
- 工具结果被剪裁时给 `next_offset`，模型带 `offset` 再取一页。`next_offset` 按
  **裁剪后实际返回的条数**计算，不会跳过中间几条。
- `ai_http` 是唯一新增的网络命令（Rust 侧），负责：拼 header、发一次请求、返回解析后的 JSON；
  **不重试、不解析业务字段**，业务校验全在 JS 里（便于测试）。
- 新增依赖 `ureq`（纯 Rust + rustls，无 OpenSSL）：约 +1.2 MB。**为什么不用前端 fetch**：
  本地 Ollama / llama-server 默认不发 CORS 头，前端 fetch 会被拦；而且密钥会出现在页面上下文里
  （调试口一开就能读）。这一条是硬需求，不是偏好。

```
用户提问
   │
   ▼
[ 前端 ai/agent.js ]  ←── 会话状态（内存 + 磁盘 JSON）
   │  ①组装消息（稳定前缀 + 变化段）
   ├─────────────► ai_http（Rust）──► 用户配置的 OpenAI 兼容端点
   │◄──────────── 一步 JSON（tool 或 answer）
   │  ②校验 schema → 不合法则 1 次修复重试
   ├─────────────► 工具调用（现有 invoke：top_files / apps.list / scan …）
   │◄──────────── 工具结果（截断到 400 token 内）
   │  ③ 回到 ①，或产出 answer + 依据 + 建议动作
   ▼
[ 界面 ] 回答 / 工具步骤卡 / 依据链接 / 建议动作卡（需用户点击）
```

## 四、工具面：8 个，全部只读

**没有任何写操作工具**（删除、移动、清理、卸载、解压都不在表里）。这不是「模型不会调」，
是「调不到」——能力隔离比提示词可靠。

| # | 工具名 | 底层命令 | 参数 | 返回（都截断） | 用在哪 |
|---|---|---|---|---|---|
| 1 | `list_dir` | 新增 Rust `list_dir` | `{dir, limit≤200}` | 条目：名/类型/大小/mtime，目录优先，`total`+`truncated` | 「这个目录里有什么」 |
| 2 | `top_files` | 现有 `top_files` | `{dir, limit≤50}` | 大文件：路径/大小/ext | 「什么占地方」 |
| 3 | `empty_dirs` | 现有 `scan_empty_dirs` | `{dir, depth≤3}` | 空目录 + `protected` 原因 | 「哪些能清」 |
| 4 | `file_signals` | 现有 `file_signals` | `{paths≤20}` | 公司/产品/签名状态/签名者 | 「这是哪来的、可不可信」 |
| 5 | `installed_apps` | 引擎 `apps.list` | `{filter?}` | 名称 + 安装路径（不带图标） | 「属于哪个软件」 |
| 6 | `search_files` | 引擎 `search.query` | `{q, limit≤20}` | 命中的路径 + 大小 | 「那个文件在哪」 |
| 7 | `organize_preview` | 引擎 `scan`（dry-run） | `{paths, recursive}` | 计划分组 + 跳过原因（不写盘） | 「会怎么分、为什么没整理」 |
| 8 | `last_organize` | 引擎 `history_list` | `{}` | 最近一次整理的目录/时间/条数 | 「上次动了什么、能不能撤销」 |

**按上下文裁剪工具集**（对应规律 3）：

| 页面 | 启用工具 |
|---|---|
| 空间工具 | 2、3、4、5 |
| 整理 | 1、7、8、5 |
| 搜索 | 6、1、5 |
| AI 助手页（全局） | 全部 8 个 |

工具描述限制在 1 行 + 参数说明，总 tool schema 控制在 ~700 token；
`installed_apps` 这类大结果必须由模型带 `filter`，无 filter 时只回前 20 个并附「共 N 个」。

## 五、主循环

```
turn(userText, ctx):
  msgs = [system(stable) , summary(if any)] + recentTurns(≤3) + [user(userText, ctxHint)]
  steps = 0
  while steps < MAX_STEPS(=6) and tokens < TURN_BUDGET(=8000):
      r = ai_http(msgs, tools=ctxTools, response_format=json_object, timeout=20s)
      obj = parse(r)                       // 失败 → repairOnce
      if obj.answer:
          return {answer: obj.answer, evidence: obj.evidence, suggest: obj.suggest, trace}
      if obj.tool not in ctxTools:          // 越权（模型幻觉出的工具名）
          msgs += assistant(obj) + toolError("工具不存在：" + obj.tool)
          continue
      result = callTool(obj.tool, obj.args) // 单个工具 8 s 超时，失败也回给模型
      msgs += assistant(obj) + toolResult(truncate(result, 400 tokens))
      steps += 1
  return {answer: 本地兜底回答, degraded: true, trace}
```

预算常量（都可配置，默认值）：

| 常量 | 默认 | 理由 |
|---|---|---|
| `MAX_STEPS` | 6 | 6 步足够「列目录 → 看签名 → 查软件 → 回答」；再多人也看不懂 |
| `TURN_BUDGET` | 8000 token | 小模型的舒适区；超过就先压缩再发（§6） |
| `CALL_TIMEOUT` | 20 s | 本地 4B 模型首 token 可能 3–8 s |
| `TOOL_TIMEOUT` | 8 s | 工具都是本地读盘，超时说明目录异常大 |
| `TOOL_RESULT_CAP` | 400 token | 一条工具结果超过就截断并标 `truncated` |
| `REPAIR_RETRY` | 1 | 只修一次；第二次失败就降级，不做无限重试 |

## 六、上下文预算与压缩

按「占用达阈值就动作」分级（对应规律 4），保护最近 3 轮原文：

| 占用 | 动作 | 说明 |
|---|---|---|
| ≤ 50% | 不动 | 正常聊天区间 |
| 50–70% | 软裁剪 | 最早的工具结果留头 8 行 + 尾 2 行 + 「共 N 项，已截断」 |
| 70–85% | 硬裁剪 | 更早的工具结果替换为一行「已省略：<工具> <参数摘要> <条数>」 |
| ≥ 85% | 摘要压缩 | 把「最近 3 轮之前」的对话交模型压成 ≤200 字摘要，替换原文；**摘要里必须保留**：用户明确说过的路径、否定结论（「这个不能删」）、未完成的问题 |

另外三条硬规则：

1. **稳定前缀字节不变**：system 提示词 + 工具 schema 拼成一段，同一会话内不改一个字（改了就掉 KV cache）。
2. **变化段只放必要信息**：页面上下文（当前目录、选中文件）用一行紧凑格式，不放原始 JSON。
3. **数字要留证据**：「13 GB」这种结论必须和工具返回的字节数同源，不允许模型自己算。

## 七、结构化输出与校验

要求模型回一个 JSON 对象（二选一，取决于端点能力）：

```json
{"thought": "看下这个目录里最大的几个文件", "tool": "top_files", "args": {"dir": "D:\\Downloads", "limit": 20}}
```
```json
{"answer": "这 3 个可以删，另外 1 个建议先确认。",
 "evidence": [{"tool": "file_signals", "paths": ["D:\\Downloads\\setup.exe"]}],
 "suggest": [{"action": "delete", "paths": ["D:\\Downloads\\a.iso"], "why": "安装包已安装，且 300 天未改动"}]}
```

校验（顺序执行，任一失败走降级）：

1. 是合法 JSON 对象；2. 只有一个顶层意图键（`tool` 或 `answer`）；
3. `tool` 在白名单内且参数通过类型/范围校验（如 `limit≤200`）；
4. `answer` 是字符串且 ≤600 字；`suggest` 的 `action ∈ {delete, archive, check, none}`；
5. `evidence` 里的工具名必须是本轮实际调用过的（防止编造依据）。

失败处理：把「错在哪」回给模型修一次；仍失败 → 用本地规则结论作答并标注「AI 输出无效，已退化为本地判断」。

对本地模型额外给一段 GBNF/JSON-schema 语法（llama.cpp 系端点支持），把「格式对」交给解码器而不是提示词。

## 八、用户提问的交互设计（本版重点）

### 8.1 三个入口

| 入口 | 形态 | 场景 |
|---|---|---|
| 导航第 12 项「AI 助手」 | 整页聊天 | 从零问、查历史、多轮追问 |
| 空间工具工具栏「问 AI」 | 右侧抽屉（不跳页） | 带着当前列表问「这几个能删吗」 |
| 整理预览页「为什么这样分」 | 抽屉 + 预填问题 | 解释分类与跳过原因 |

抽屉复用同一个 `agent.js` 与同一份会话存储，只是初始上下文不同。

### 8.2 界面构成

### 8.3 提问能力清单（v1 必须有）

| 能力 | 具体行为 |
|---|---|
| 自由提问 | 单行输入，Enter 发送、Shift+Enter 换行，输入框自动长高 |
| 追问 | 保留最近 3 轮原文 + 更早的摘要；「它们」「这个」「刚才那个」由模型自己指代，界面上不要求用户重复路径 |
| 建议追问 | 每次回答后给 2 条 chip，来自本次工具结果（如「要不要看下这 3 个文件的签名？」），点了直接发 |
| 停止 | 立刻停止继续发下一步；已产生的步骤卡保留并标「已停止」 |
| 重试 | 对最后一条回答可重试；重试会丢弃上一次的步骤与结论 |
| 引用依据 | 每条结论后面 `[依据]`，展开是工具名 + 参数 + 原始返回片段（截断显示），可跳转到文件 |
| 建议动作卡 | `suggest` 渲染成卡片，按钮只做「跳到对应页面并预填选择」，真正的执行仍走原有确认弹窗 |
| 复制回答 | 一键复制纯文本（带依据列表） |
| 会话管理 | 新会话、最近 20 个会话列表、删单个、清空全部 |
| 空态引导 | 未配置时整页三步引导（填地址 → 填密钥 → 选模型 → 测试连接），配好后直达 |

### 8.4 不做什么（避免把聊天做成万能入口）

- 不回答与本软件无关的问题（写代码、闲聊、翻译）：直接说「我只管文件和空间这一块」，
  并给一条它能做的事作为引导。**不做**「全能助手」的承诺。
- 不猜文件内容：没有内容读取工具，答案里禁止出现「这个文件里写着…」这类说法（system 里明令禁止，
  且工具面不支持，模型无法凭空拿到）。
- 不做命令执行：模型不能拼 shell，也不能给用户一段命令让用户复制去跑。

## 九、会话与存储

```
%LOCALAPPDATA%\整理助手数据\ai\
    sessions\<session-id>.json    会话（消息、步骤、结论），最多 20 个，最旧自动删
    facts\<hash>.json             事实缓存：路径+大小+mtime → {ext, sig, company, owner}，7 天
    settings.json                 端点、模型名、开关（密钥单独存，见 §11）
    usage.jsonl                   每轮一行：时间、步数、token、耗时、成功与否（不含提问原文）
```

- 会话文件用 `read_text` / `save_text` 现有命令读写（无需新增存储命令）。
- 单会话上限 100 条消息 / 2 MB，超了截断最旧的并记一行「更早内容已折叠」。
- 事实缓存命中时不再调工具，直接进上下文，能显著减少步数与 token。

## 十、安全边界（四条硬规矩）

1. **能力隔离**：工具表里没有写操作（§4）。模型即使输出 `{"tool":"delete"}` 也只会收到
   「工具不存在」，永远到不了引擎。
2. **建议不等于执行**：`suggest` 只渲染卡片，按钮是导航，不是执行；执行必须用户在原页面点确认
   （现有 `ui.js` 的 danger 确认框已经做了焦点在「取消」、拦 Enter 连发）。
3. **参数绑定**：建议卡上写死它建议的具体路径；用户如果在目标页面改了选择，卡片失效并提示「已按你当前的选择执行」。
4. **越权与幻觉一律拒绝**：工具名不在白名单、参数越界、`evidence` 引用了没调用过的工具，
   都按失败处理并在步骤卡上标红，不做「猜你想调」。

## 十一、隐私

| 项 | 规定 |
|---|---|
| 发什么 | 只发元数据：路径（可脱敏）、文件名、大小、扩展名、mtime、签名状态、所属软件名 |
| 不发什么 | 文件内容、缩略图、注册表原始值、历史记录全文、日志原文 |
| 脱敏 | 默认把 `C:\Users\<用户名>\` 折叠为 `%USERPROFILE%\`，设置里可关 |
| 发送前确认 | 首次开启弹一次说明；每次发送前可点「将要发送的内容」预览（纯文本，可复制） |
| 密钥 | 单独存放（`ai\settings.json` 的 `key` 字段），界面上只显示后 4 位；日志与 usage 里绝不出现 |
| 可关可清 | 一个总开关；「清除 AI 数据」删会话、事实缓存、usage、密钥；关掉后所有入口变灰并提示 |

## 十二、失败与降级

| 情况 | 表现 | 是否影响其它功能 |
|---|---|---|
| 未配置 / 总开关关 | 入口禁用 + tooltip「先在设置里配 AI 助手」 | 否 |
| 端点连不上 / 超时 | 该步失败，回给模型重试 1 次；仍失败则输出「AI 没响应」+ 本地结论 | 否 |
| 401 / 403 | 「密钥无效」并停止本轮，不再重试；设置页给「测试连接」 | 否 |
| 429 | 「额度或频率受限」，把建议重试时间显示出来 | 否 |
| 返回非 JSON | 修复重试 1 次；仍失败 → 本地结论 + 标注 | 否 |
| 工具报错（目录不存在等） | 错误文本回给模型，让模型换参数或换工具 | 否 |
| 步数用尽 | 用已有信息作答，标注「信息可能不全，可以继续追问」 | 否 |
| 用户点停止 | 立刻结束在飞请求，保留已完成步骤与断点，标注「已停止」+「继续」按钮 | 否 |
| 本地模型太慢 | 显示「本地模型较慢（已等 12 秒）」，可切云端点 | 否 |

**总原则：AI 任何异常都不阻塞列表、扫描、整理、删除等既有功能**（与 v1 相同）。

## 十三、可测性：离线黄金集

AI 功能最怕「上线才发现全是幻觉」。所以先设计测试再接模型（对应规律 6）：

- **假模型**：`ai_http` 在测试模式下指向本地脚本化服务，按预置脚本回固定 JSON（含故意坏掉的分支）。
  脚本化服务只有 60 行 Python（`http.server`），不引入依赖。
- **黄金集 28 条**，每条 = `{问题, 上下文, 脚本化模型响应序列, 期望工具序列, 期望结论要点}`，覆盖：
  1. 单步问答（不需要工具）4 条
  2. 两步（列目录 → 查签名）6 条
  3. 三步以上（列目录 → 查软件 → 回答）4 条
  4. 工具报错后改参数 3 条
  5. 越权调用（`delete` / `move`）被拒 2 条
  6. 非 JSON / 缺字段 → 修复后成功 3 条
  7. 步数耗尽降级 1 条
  8. 上下文压缩后仍能正确回答 1 条
  9. 一步两个独立查询（G25，验证只花一步）1 条
  10. 大目录结果分页，`next_offset` 与实返条数一致（G26）1 条
  11. 慢模型下停止必须立刻返回、并留下断点（G27，假模型故意延迟 300 ms）1 条
  12. 断点续跑不重复走步数（G28）1 条
- **可测下限**（每次改动都跑，写在 `agent.selftest.mjs` 里）：
  - schema 合法率 = 100%
  - 越权拦截率 = 100%（这条最硬）
  - 期望工具序列完全匹配 ≥ 20/28
  - 断言回答里每个数字都能在工具返回里找到（证据可追溯）
  - 单轮 token 不超预算
  - 停止延迟 < 150 ms（假模型 300 ms，等到超时就说明取消没生效）
- 真模型冒烟：手动跑 6 条真实提问，记录耗时与是否引入幻觉，写进交付报告（**不自动跑，避免把测试成本算到用户头上**）。

## 十六、明确不做

- 不做自动删除 / 自动迁移 / 自动清缓存（工具面里没有写操作，这是结构性的，不是承诺）。
- 不读文件内容、不做 OCR、不做杀软替代。
- 不内置任何第三方 key，不代用户付费，不把密钥上传到任何中转。
- 不把 AI 结论写进整理历史（历史只记真实发生的移动）。
- 不做 MCP server、不做语音、不做多轮任务编排（定时自动跑）。
- 不在没有用户点击的情况下改变任何文件状态。
