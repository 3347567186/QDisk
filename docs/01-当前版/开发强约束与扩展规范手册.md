# 整理助手 · 开发强约束与扩展规范手册（1.43.0 起强制生效）

> **最高指令**：任何后续接手开发者、维护工程师或 AI Agent 在阅读或修改本仓库代码前，**必须先完整阅读本手册及 `AGENTS.md`**。
> 凡涉及新增顶层模块、修改架构边界、改变存储格式或突破下述六条红线的需求，**必须先停止编码并向软件作者（开发者）说明影响范围与替代方案，获得明确书面同意后方可实施；严禁擅自越界开发、偷改基础设施或引入未授权依赖。**

## 一、六条核心工程红线（不可违反）

### 红线 1：全链路纯 ASCII 路径与脚本编码兼容
1. **路径红线**：唯一源码树固定为 `D:\Tools\TidyAssistant`，构建中间目录固定为 `D:\Builds\`。禁止将源码、Rust `target`、PyInstaller 临时目录或任何脚本置于包含中文或空格的路径中，禁止将构建缓存放回 `%TEMP%` 或 `src\src-tauri\target`。
2. **PowerShell 编码红线**：仓库内所有 `.ps1` 脚本（`build.ps1`、`tools\build-manager.ps1`、`tools\gen-ai-pool.ps1` 等）**必须采用 UTF-8 with BOM 编码**。Windows PowerShell 5.1 在无 BOM 时会将中文引号/书名号误判为语法错误，所有构建或辅助脚本提交前必须在 Windows PowerShell 5.1 与 PowerShell 7（`pwsh`）下双通验证。

### 红线 2：工作区整洁、零残留与自动化门禁清理
1. **外部边界**：`D:\Tools\` 下仅保留 `TidyAssistant` 目录；禁止在仓库外部散落临时测试文件、调试转储或探测目录。
2. **内部边界**：禁止在仓库内保留 `__pycache__`、`*.pyc`、`src\src-tauri\target`、`src\engine\数据`、`src\engine\in.txt` 或废弃原型目录。
3. **强制清理钩子**：`build.ps1` 在 Git 快照前自动调用 `Clear-TidyWorkspaceResidue`，且 Python 测试门禁固定通过 `D:\Builds\engine-venv\Scripts\python.exe -B`（配合 `PYTHONDONTWRITEBYTECODE=1`）执行，防止测试污染 Git 工作树。

### 红线 3：页面模块生命周期与三大标准布局骨架
1. **12 个标准页面清单**：`ai`、`organize`、`shots`、`cache`、`tools`、`archive`、`search`、`rules`、`apps`、`migrate`、`log`、`settings`。
2. **完整生命周期契约**：每个页面模块在 `window.Pages.<id>` 下必须声明：
   - `title: [zh, en]`（及可选 `subtitle: [zh, en]`）；
   - `async mount(root)`：**必须返回 `unmount()` 清理函数**（或提供模块级 `unmount()`）；
   - `unmount()` **必须彻底回收本页生命周期内创建的全部资源**：包括 `setInterval` / `setTimeout`、`document.addEventListener` / `window.addEventListener`、`ResizeObserver`、顶栏动作区 `UI.setActions()`、以及挂到 `window.App._onPageSize` 等全局回调，严禁跨页幽灵轮询或事件泄漏（由 `pages.selftest.mjs` 双轮挂载回归测试强制校验）。
   - `jump(payload)`：供 AI 助手建议卡、`navigate` 工具与页间联动调用，支持直达子标签页（如 `apps` 的 `procs` / `startup` / `footprint`、`tools` 的 `big` / `empty` / `browse`）或预填路径/规则草稿。
3. **三大标准视觉骨架（禁止新造散装排版与未登记样式）**：
   - **骨架 I · 分段定高工作台（`.wb-bar` + `.wb-pane` + `.stretch-card`）**：适用于同页多模态高密度数据操作页（如 `tools`、`apps`、`search`、`cache`、`shots`、`archive`）。切换子面板通过 `.wb-bar` / `.wb-tabs` 完成，禁止将核心高频工作区塞进三块各自折叠的大盒子。
   - **骨架 II · 双栏主从工作台（`.split-wb` / `.split-wb.master-detail`）**：适用于「清单/编辑 + 预览/日志」双向联动页（如 `rules`、`log`、`migrate` 源与配置协同区），宽屏左右联动对照、窄屏（`<= 980px`）自动单列堆叠。
   - **骨架 III · 紧凑流式配置工作台（`.set-nav-bar` + `.set-card` + `.set-row`）**：适用于分组设置页（`settings`），顶部吸顶快速跳转胶囊 + 手风琴分组折叠。
4. **样式与交互铁律**：颜色/圆角/间距/阴影全部引用 `styles.css` 设计令牌；文本说明最多 2 行截断；禁止列表逐行入场动画与空闲 CPU 轮询；图标统一使用 `UI.icon(name, size)`。

### 红线 4：AI Agent 全功能深度融合与只读/提案安全边界
1. **全页一致顶栏副驾**：除 `ai` 整页对话外，其余 11 个功能页均须在 `mount()` 中通过 `UI.setActions(..., UI.askBtn({...}))` 在右上角挂载统一视觉入口（带当前页与活跃区块动态上下文 `ctx`），并在 `unmount()` 中调用 `UI.setActions()` 卸载。
2. **工具（`AITools` / `AIPrompt`）与页面同步扩展**：
   - 所有新增只读诊断能力须注册到 `AIPrompt.TOOLS`、`AIPrompt.PAGE_TOOLS` 与 `AITools.makeTools()`，返回结果必须经过 `fit(..., CAP)` 裁剪并遵守超时约束；
   - `toolSchema()` 会自动导出 `TOOLS[n].params` 的全量参数，保持 `required: TOOLS[n].args` 准确无误；
   - `navigate` 工具支持全 12 页与语义别名直达（`clean` → `cache`、`screenshots` → `shots`、`logs` → `log`、`processes` → `apps(procs)`、`startup` → `apps(startup)`、`footprint` → `apps(footprint)`），且在 `readonly` 只读模式下也允许安全导航（仅切换界面，不改盘）。
3. **写操作双闸门（`AIGuard` + `AIRegistry` + `AIProposals`）**：
   - 任何会修改磁盘、进程、自启项、配置或清理的操作，**禁止直接作为 `AITools` 暴露给模型**；
   - 必须通过 `AIRegistry` 定义 `{ plan, run, risk, reversible, undoKind }` 纳入 `propose_action` 通道：`plan()` 只读预演真实影响，`run()` 仅在用户审批（`proposals.commit`）后触发；禁止在 `agent` 或界面绕过 `AIGuard.denyWhy()` 路径保护与 `is_system` 进程保护。
4. **免费模型池与故障转移纪律**：
   - `agent.js` 的 V2 被动学习（单 slug 指数冷却 `60s -> 300s -> 1800s`、HTTP 200 空回复降级、401/403 不写冷却、账号日限额跨站切换）与 V3 本地 Ollama 尾备（`ollamaFallback`）相关能力字段必须在 `store.js` 的 `normalize()` 中白名单保留，禁止丢失冷却记忆。

### 红线 5：唯一构建、版本递增与测试门禁通道
1. **禁止绕过 `build.ps1`**：严禁直接运行 `cargo build` / `cargo tauri build` 或手工修改 `tauri.conf.json` / `Cargo.toml` 版本号。
2. **构建前全量门禁**：`build.ps1` 执行全量构建前必跑全部 Node 自测（`*.selftest.mjs`）与 Python `unittest`（`-B` 禁止生成字节码），任一门禁失败立即阻断构建。
3. **文档同步义务**：功能与契约变更必须同步更新 `前端页面契约.md`、`src\web\js\CONTRACT.md`、`UI设计规范.md` 与 `变更记录.md`。

### 红线 6：越界改动强制审批条款（最高优先级）
如后续开发任务涉及以下任一情况，**必须暂停实现、先向用户提出明确申请并获得同意后再动手**：
1. **架构与页面增删**：新增/删除/合并顶层 12 个导航页面之一，或更改 Rust + Tauri + Python Engine + 原生 JS 技术栈（如引入 npm 构建链/第三方 UI 框架）。
2. **数据与安全边界突破**：修改 `%LOCALAPPDATA%\整理助手数据` 或 `引擎\数据位置.json` 的存储位置与结构；放宽 `AIGuard` 危险目录黑名单；允许模型绕过用户审批直接写盘或执行任意系统命令。
3. **核心体验与包体红线突破**：引入常驻后台轮询或高耗电动画；向 `整理助手引擎.spec` 引入重型科学计算/GUI 依赖导致便携包体积显著膨胀。
4. **规范本身修改**：删改或弱化本手册中的任何红线条款。

## 二、新功能标准接入检查清单（Checklist）

每次按用户要求新增功能或扩展页面时，须依次核对以下各项并在交付前自证通过：

| 检查维度 | 必须满足的验收标准 | 对应验证方式 |
|---|---|---|
| **架构与路径** | 无中文路径、无 `target` / `__pycache__` / 外部散落文件；`.ps1` 为 UTF-8 BOM | `build.ps1 -Status`（PS 5.1 + PS 7） |
| **引擎 RPC** | `tidy.py` 新增 `_ENGINE_METHODS` 写操作带 `confirm` 参数与危险路径校验；有 `unittest` 覆盖 | `python -B -m unittest ...` |
| **前端页面** | 符合 3 大布局骨架之一；实现 `mount` 返回 `unmount` + `jump` + `UI.askBtn`；无硬编码色值 | `node src\web\js\ai\pages.selftest.mjs` |
| **AI 深度融合** | 补齐只读诊断工具（`prompt.js` + `tools.js` + `chatui.js`）与可控提案动作（`registry.js`） | `actions.selftest.mjs` + `agent.selftest.mjs` |
| **文档与版本** | 同步契约/设计文档与 `变更记录.md`；通过 `build.ps1 -Bump <位>` 生成一致产物 | `build.ps1 -Bump minor/patch` |
