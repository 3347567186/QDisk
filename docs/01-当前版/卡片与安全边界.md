# 卡片尺寸、显示数量与清理安全边界

本文件锁定三件容易在迭代中被「优化掉」的东西：卡片尺寸、每屏数量、删除类操作的边界。
改动它们之前先读 `docs/01-当前版/版本管理与发布规范.md`，改完必须递增版本号。

## 一、尺寸令牌（`src/web/styles.css` 顶部）

| 令牌 | 值 | 约束对象 |
|---|---|---|
| `--card-max` | 520px | 单张卡片的最大高度，超出内部滚动/分页，不拉高整页 |
| `--stat-h` | 96px（窄屏 88px） | 顶部统计卡固定高度，数字与标签不换行撑高 |
| `--row-h` | 36px（`--row-h:30px` 见表头） | 表格单行高度，超长文本省略号截断 |
| `--row-h`（表格） | 30px | `.table.dense` 紧凑行高 |
| `--thumb-h` | 150px（窄屏 120px） | 截图缩略图可视高度，`object-fit: cover` 裁切 |

规则：

- 卡片高度只由令牌决定，**不允许**因为数据条数、文件名长度、徽章数量而变化。
- 表格 `th/td` 固定 `height` + `max-height` + `white-space: nowrap`；需要两行说明时用 `.clamp-1/.clamp-2`，不要放开行高。
- 缩略图容器固定高度并 `overflow: hidden`，图片 `object-fit: cover`；不得用图片原始比例撑高网格。

## 二、每屏显示数量（分页，不是无限滚动）

| 页面 | 上限 | 实现 |
|---|---|---|
| 卸载程序 | 50 / 页（可选 100） | `apps.js` 分页器 |
| 清理缓存 | 200 / 组 / 页 | `cache.js` 组内分页 |
| 清理截图 | 200 / 页 | `shots.js` 分页 |
| 空间工具 · 大文件 | 50 行 | Rust `top_files(dir, limit)`，附类型/来源/风险标签 |
| 整理预览 | 全部组，组内折叠 | 分组折叠 + 组全选 |

**禁止**给 `.page-body` 或卡片内部新增 `overflow: auto` 的滚动容器——全软件只有一个滚动条（`#scroll`）。
`styles.css` 里 `.table-wrap` 已改为 `overflow: visible`，就是为了防止双层滚动。

## 三、加载态：全软件统一动画

- 组件：`src/web/js/cursor-loader.js`（`window.CursorLoader`），Canvas2D 画 7 支彩色光标搭页面的循环动画。
- 遮罩加载：`UI.busy()` 首次调用把 loader 挂进 `#overlay`（150px 高），文案走 `setLabel`。
- 骨架加载：`UI.skeleton(rows)` 返回 `.loading-block`，高度 `min(260, max(96, 96 + max(0, rows-3)*18))`，**不随数据量膨胀**。
- 缺失兜底：`window.CursorLoader` 不存在时退回旧灰条骨架，页面不会空白。
- 无障碍：`prefers-reduced-motion: reduce` 时组件降级为静态帧；离屏（`IntersectionObserver`）自动暂停。

## 四、删除类操作的红线

引擎（`src/engine/tidy.py`）已有的闸门：

| 入口 | 闸门 |
|---|---|
| `files.delete` | `_files_delete_guard_why`，拦截盘符根、系统目录、程序目录 |
| `cache.clean` | `cache_path_forbidden` + `is_drive_root`；个人目录（文档/桌面/图片/视频/音乐/OneDrive/.ssh/.git）一律不碰 |
| `apps.force_remove` | 盘符根、`SystemRoot`、`USERPROFILE` 拒绝；只删该程序的安装目录与注册表项 |
| `apps.delete_entry` | 只删注册表卸载项，不动文件 |
| `apps.cleanup` | 只删扫描出的残留目录与注册表键 |

外壳（`src/src-tauri/src/main.rs`）本轮补的闸门：

- `remove_empty_dirs` 调用前必须过 `empty_dir_denied(path)`：盘符根、`SystemRoot`、`USERPROFILE`、
  `ProgramFiles`/`ProgramFiles(x86)`/`ProgramData`/`PUBLIC`、任何 `\windows\` 路径一律拒绝，返回 `{path, why}`。

必须保持的不变量：

1. 任何删除都先 `confirm`，UI 侧二次确认；`force_remove`、`delete_entry`、`permanent` 删除不可撤销，确认文案要写明。
2. 默认走回收站（`mode: trash`），永久删除只在用户明确选择时出现。
3. 不新增「按目录递归删」的通用命令；要删就删扫描结果里的具体条目。
4. 新增危险操作时，先在这里补一行闸门说明，再写代码。

## 五、多光标组件（MultiCursorBuilder）

独立组件，源码在 `src/web/components/MultiCursorBuilder/`：

```
MultiCursorBuilderEngine.js   # 框架无关引擎（Canvas2D 光标 + 滚动编排 + 全套样式注入）
MultiCursorBuilder.tsx        # React 包装
motion-runtime.ts             # 缓动 / Ticker / 字体引用计数 / reduced-motion
MultiCursorBuilderEngine.d.ts # 对外类型
entries/{vue.js,svelte.svelte,solid.jsx,preact.jsx,vanilla.js}
demo.html                     # 双实例演示，含 Replay/Pause/Skip intro
```

用法（Vanilla）：

```js
import { mountMultiCursorBuilder } from './entries/vanilla.js';
const inst = mountMultiCursorBuilder(document.getElementById('host'), { height: 760 });
// inst.replay() / inst.pause() / inst.resume() / inst.setOptions({...}) / inst.destroy()
```

约定：

- 组件自身不监听全局滚动，只观察宿主元素进入视口后的内部滚动进度；不进视口就暂停。
- 宿主高度由调用方给定，组件不撑破容器；`ResizeObserver` 只影响画布尺寸。
- 卸载必须 `destroy()`，否则 `Ticker` 与 `ResizeObserver` 会持续占 CPU。

## 七、加载动画的适用范围（1.0.1 起）

多光标动画不是「日志页专用」，它是全软件唯一的加载表达。接入点：

| 场景 | 接入方式 | 位置 |
|---|---|---|
| 首屏启动 | `#page` 内静态 `[data-cursor-loader]`，`cursor-loader.js` 自动挂载 | `src/web/index.html` |
| 侧边栏切页 | `navigate()` 先挂 `UI.pageLoading(标签)`，至少显示 180ms，挂载完成后摘除 | `src/web/js/app.js` |
| 卡片/表格数据加载 | `UI.skeleton(rows)`（内部即 CursorLoader，高度 96–260 锁定） | 各页面 |
| 全屏遮罩操作 | `UI.busy(fn, label)`（遮罩内 150px 动画） | 各页面 |
| 行内状态位/徽章 | `UI.inlineLoader(label)` | `search.js` 索引状态等 |
| 侧边栏正在打开的项 | `.nav-item.loading` 右侧脉冲圆点 | `styles.css` |

规则：

- 不允许再出现纯文字「读取中…」「加载中…」占用内容区；要么用 `skeleton()`，要么用 `inlineLoader()`。
- 不允许自写 spinner（`.spinner` 仅保留给极小的按钮内联场景）。
- 新页面接入清单：`mount()` 第一屏先用 `skeleton(n)`，数据就绪后替换；长操作包 `busy()`。
- 动画实例必须随内容替换自然销毁（`skeleton` 返回的元素被替换即可），`pageLoading` 由 `navigate()` 负责摘除。
