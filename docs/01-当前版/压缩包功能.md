# 压缩包功能（1.14.x）

## 目标与边界

在不引入 Python 压缩库、不显著增大安装包的前提下，提供接近 Bandizip 日常使用的
浏览、解压、创建与预览能力。硬约束是性能、内存和体积；格式覆盖按“常用优先”分层，
不追求 ACE/ALZ/EGG 等罕见格式。

## 架构

压缩核心在 Rust 外壳进程内，不走 Python 引擎的 JSON-RPC：

```
前端 src/web/js/pages/archive.js
        │  invoke
        ▼
src/src-tauri/src/archive/mod.rs   命令面、格式探测、进度事件
        ├── zip_impl.rs            ZIP/ZIPX 读写
        ├── sevenz_impl.rs         7z 读写、分块并行
        ├── tar_impl.rs            TAR/TGZ/TBZ2/TXZ/GZ/BZ2/XZ
        ├── rar.rs                 UnRAR64.dll 动态加载
        ├── download.rs            WinHTTP + tar.exe 引导
        ├── preview.rs             文本/十六进制/媒体落盘
        └── util.rs                路径安全、覆盖策略、进度、哈希
```

- 列表与解压都在 `spawn_blocking` 中执行，前端只收 `archive-progress` 事件。
- 7z 创建按 8 MiB 未压缩块切分，`prepare_block` 在线程池压缩，
  `push_prepared_block` 按顺序写盘；线程数由四档模式决定。
- ZIP 固定单线程 Deflate-6；不启用 zip crate 的 Rayon 并行，避免大文件峰值内存。
- 预览文件落在 `%LOCALAPPDATA%\整理助手数据\preview\<pid>-<millis>`，关闭页面时清理。

## 拖放打开

- 「打开压缩包」与「新建压缩包」两个页签都接受从资源管理器拖入的文件。
- 打开页只取第一个扩展名匹配的压缩包；同批拖入多个时提示「一次只打开一个，已打开第一个」，
  没有匹配项时提示「拖入的不是支持的压缩包格式」。
- 新建页把拖入的路径直接加入待压缩列表，不再弹选择框。
- 拖入时显示全屏虚线提示层（文案随页签切换），放下或离开即隐藏；
  `prefers-reduced-motion` 下只保留淡入淡出。

## 解压位置与命名（1.14.0）

解压不再调用系统文件夹选择器，也不再把条目散落进目标目录。点「解压选中 / 全部解压」后
先弹软件内对话框：

| 控件 | 行为 |
|---|---|
| 解压到 | 可手输，也可「浏览」用系统选择器挑父目录；默认上次使用的位置，首次为压缩包所在目录 |
| 放进同名文件夹 | 默认勾选；文件夹名默认取压缩包名去掉压缩后缀（`foo.tar.gz` → `foo`） |
| 目标预览 | 实时显示最终路径，随输入更新；路径不是绝对路径时禁用「开始解压」并提示 |
| 完成后打开文件夹 | 默认勾选，解压结束直接打开资源管理器 |

命名规则：

- 文件夹名做 Windows 合法性校验（`\ / : * ? " < > |`、控制字符、尾部点、CON 等保留名）；
  首尾空格在保存前自动去掉，所以「尾部空格」不算错。
- 压缩包自带唯一顶层文件夹且与压缩包名相同时，默认不勾「放进同名文件夹」，
  直接解压进所选位置，避免出现 `foo\foo`；勾上仍可强制多套一层。
- 顶层直接有文件的压缩包无法自动判断，默认仍建同名文件夹；取消勾选时提示会散落。
- 单文件压缩包（`foo.txt.gz`、`data.csv.bz2` 这类）的条目名与压缩包去掉后缀后的名字一致时，
  文件夹名再取一次去扩展名的名字（`foo`），避免出现 `foo.txt\foo.txt`。
- `archive_extract_dir`、`archive_extract_open` 写入配置，下次打开对话框沿用。

压缩侧对称处理：新建压缩包不再弹系统「另存为」，改为同样的软件内对话框
（保存到 / 文件名 / 最终路径预览），文件名没有已知压缩后缀时按所选格式补全
（`备份.2024` → `备份.2024.zip`；已写 `.7z`、`.tar.gz` 等则原样保留，格式不符会先确认）；
目录记在 `archive_create_dir`。压缩包页仍保留系统文件夹选择器用于「添加文件夹」这类
选源操作。

## 进度与实时速率（1.15.0）

解压/压缩进行时右下角固定浮出 320px 的进度小窗（`.arc-progress`），不遮挡主内容。
1.15.0 起小窗里多一条 56px 高的速率折线，宽度跟着小窗走，**不改变小窗尺寸**。

- 数据来源：Rust 侧 `archive-progress` 事件（`util.rs` 的 `emit()`，节流 90ms），
  字段 `bytes` / `total_bytes` / `files` / `total_files` / `phase` / `name`。
- 采样：`sampleSpeed()` 用相邻事件的时间差算瞬时字节速率，间隔小于 40ms 的丢弃；
  第一条事件只记基线并垫一个 0，曲线从底边起步；指数平滑 `ema = ema * 0.6 + inst * 0.4`；
  环形样本上限 56 条（约 5 秒窗口）。
- 绘制：`buildSpeedChart()` 输出 `viewBox="0 0 296 56"` 的 SVG，`preserveAspectRatio="none"`
  横向铺满；面积用 `arcSpeedFill` 渐变，折线加 `vector-effect="non-scaling-stroke"` 防止被拉粗；
  底部 2px 亮线表示已处理比例。
- 文字：左下角「剩余 X」（有总字节与速度时）或「速度」/「正在准备…」，
  右下角当前速率 `12.3 MB/s`，数字用 `tabular-nums` 防跳动。
- 回退：样本不足 2 条时（读表阶段、刚起步）不画图，仍用细 `.arc-bar`，
  避免只画出一块空图；采样攒够后自动切成折线。
- 样式：`.arc-chart`（`--surface-2` 底 + `--line` 边框 + `--radius` 圆角）、
  `.arc-chart-meta`、`.arc-chart-spd`；只增加高度，不加宽度。

## 文件列表渲染规则（1.16.0）

3,000 条目曾经把整页顶长：页头、工具栏、页脚一起被推出视口，滚到底才能点「解压全部」。
1.16.0 把列表改成**虚拟滚动 + 固定页脚**，规则如下。

- 高度链：`mount()` 在 `.page-body` 里再包一层 `.page-fill.arc-body`。
  `.page-host:has(> .page-body > .page-fill)` 与 `.page-body:has(> .page-fill)`
  把页面压到窗口高度，`.arc-head` 固定、`.arc-open` 占满剩余高度，
  滚动只发生在 `.arc-table-wrap`（`flex:1 1 auto; min-height:0; overflow:auto`），
  页脚与「平衡 / 解压全部」始终贴在窗口底部。
- 只渲染视口：`renderSlice()` 按 `scrollTop` 与 `clientHeight` 算窗口，
  `start = max(0, floor(scrollTop/rowH) - 8)`、`end = min(total, ceil((scrollTop+clientHeight)/rowH) + 8)`，
  overscan 固定 8 行（`VROW_OVERSCAN`）。上下各插一个 `<tr class="arc-spacer">`
  撑出总高度，中间用 `DocumentFragment` 插行；3,000 条时 DOM 里只有 30~50 个 `<tr>`。
- 行高：优先读 `.arc-table-wrap` 的 `--row-h` 再加 1px 分隔线，取不到兜底 33px；
  首帧渲染后量一次真实行高，偏差超过 1px 就更新并重画，避免缩放后行错位。
- 滚动：`scroll` 事件用 `requestAnimationFrame` 合帧，滚到底时补画；
  `ResizeObserver` 监听 `.arc-table-wrap`，窗口拉伸时按新视口重算。
- 行模型缓存：`buildRowsFor(cwd)` 每次进目录只扫一遍 `entries` 建行，
  按 cwd 存进 `S.rowsByCwd`；`currentRows()` 的视图 key 是
  `path + cwd + filter + sortKey + sortDir`，命中就直接复用上次的数组，
  换排序/筛选才重新过滤排序。关包、切包时 `resetRowCaches()` 清空。
- 勾选不重渲染：`toggleKey()` 只改命中行的 `selected` 类和 checkbox 状态，
  再刷页脚计数；不再重建整张表。
- 筛选防抖 120ms：连续输入只触发一次重建；全选只重画可视区（`renderSlice(true)`）。
- 选中换算：`entryIndex()` 建一次 `norm(name) → entry` 的 Map，
  普通项 O(1) 拿 index；目录 key 才遍历整个 Map 取前缀匹配。
- 空态与无包：清空 tbody 并显示原来的空状态，不保留旧行。

## 支持格式

| 能力 | 格式 |
|---|---|
| 列表/解压 | ZIP、ZIPX、7Z、RAR、RAR5、TAR、TAR.GZ/TGZ、TAR.BZ2/TBZ2、TAR.XZ/TXZ、GZ、BZ2、XZ |
| 创建 | ZIP、7Z、TAR、TAR.GZ |
| 加密读取 | ZIP AES/ZipCrypto、7z AES-256、RAR AES |
| 加密创建 | ZIP AES-256、7Z AES-256 |

RAR 只读，不提供创建。

## 安全

- 解压前对每个归档内名称调用 `safe_relative`：拒绝绝对路径、盘符、UNC、
  `..`、NTFS ADS、控制字符、尾部点/空格、CON/PRN/AUX/NUL/COM1-9/LPT1-9。
- 单次解压总上限 32 GiB；预览文本 2 MiB、媒体 16 MiB、二进制（十六进制视图）
  64 KiB。二进制只转储前 64 KiB 是为了压住渲染量：以前 4 MiB 会拼成约 20 MB
  的单个字符串塞进一个 `<pre>`，实测卡死 35 秒、内存 1.4 GB（1.16.5 改）。
- ZIP 符号链接条目跳过；RAR 重解析点/符号链接跳过；7z anti-item 跳过。
- 覆盖策略：覆盖、跳过、自动改名（`name (2).ext`）。
- RAR DLL 只从固定 URL 下载，SFX 与 DLL 双重 SHA-256 校验；
  校验失败重试 3 次，仍失败则只禁用 RAR。

## 首次使用 RAR

1. 检查 `%LOCALAPPDATA%\整理助手数据\bin\unrar\UnRAR64.dll` 是否存在且可加载。
2. 不存在则下载 `https://www.rarlab.com/rar/unrardll-710.exe`（816,080 B）。
3. 校验 SFX SHA-256 `34874EF0…D5F3`。
4. 用系统 `tar.exe` 只提取 `x64/UnRAR64.dll`（398,992 B）。
5. 校验 DLL SHA-256 `D3F371AD…AA90`，原子改名后加载。

不执行 SFX，不把 DLL 打进安装包。

## 性能基线

语料：427 文件 / 78.8 MB（25 MB 文本 + 24 MB 随机二进制 + 8 份 exe/字体）。

| 操作 | 结果 | 时间 | 峰值内存 |
|---|---|---|---|
| ZIP Deflate-6 | 43.15 MB | 2.18 s | 8.8 MB |
| 7z L3、8 MiB 块、1 线程 | 30.29 MB | 18.3 s | 56.7 MB |
| 7z L3、8 MiB 块、2 线程 | 30.29 MB | 9.7 s | 94.6 MB |
| 7z L3、8 MiB 块、4 线程 | 30.29 MB | 5.0 s | 137.3 MB |
| 7z 解压 | — | 1.45 s | 3.8 MB |
| TAR.GZ-6 | 42.97 MB | 2.38 s | 8.6 MB |

体积：核心 +0.85 MB；UnRAR64.dll 0.39 MB（首次下载）；exe 约 4.92 MB。

## 验证记录

- ZIP：3 条目打开、文本预览、解压 3 文件；`hello.txt` SHA-256 与源一致。
- ZIP 创建：3 文件 / 6,918 B → 884 B，bsdtar 可列出完整目录结构。
- 7z：创建 3 文件 / 556 B；解压后 `hello.txt`、`blob.bin` SHA-256 与源一致。
- TAR/TGZ：创建成功，bsdtar 可列出。
- RAR5 solid：7 文件 / 25,776 B，解压到指定目录，项目根无残留。
- 路径安全：拒绝绝对路径、`..`、ADS、保留名；符号链接跳过。
- 7z 修改时间：读取 `has_last_modified_date` 与 `last_modified_date`（FILETIME），
  经 `FileTimeToLocalFileTime` 转本地时间；用 sevenz-rust2 0.25 写读回 `a.txt`、`sub`
  两个条目均得到正确时间。
- 速率折线（1.15.3）：解压 `many.zip`（3,000 个文件）逐帧抓图，折线从底边爬升并随速度起伏，渐变面积、右下角 `107 KB/s`、左下角「剩余 1 秒内」同时刷新；小窗宽度保持 320px。
- 拖放：`tauri 2.12.5` 的 `bundle.global.js` 确认 `window.__TAURI__.webview.getCurrentWebview()`
  与 `onDragDropEvent` 的 `drop` 载荷为 `{ type: "drop", paths, position }`；实机从资源管理器
  拖入非压缩包时弹出「拖入的不是支持的压缩包格式」，确认事件投递与格式判定生效。
  打开分支调用的是「选择压缩包」同一个 `openArchive`。

## 已知限制

- RAR 只读；RAR 组件首次使用需要网络。
- 7z 创建的内存随线程数上升，超线程档在超大目录上可能占用数百 MB。
- 7z 修改时间仅当压缩包确实写入 MTime 时显示；未写时间的旧包仍显示 `—`。
- 拖放走 WebView2 的 OLE 拖放，跨权限级别（例如以管理员身份运行的程序）拖入会被系统拦截。
- ZIP 创建固定 Deflate-6，不提供 store-only 或其它级别。
