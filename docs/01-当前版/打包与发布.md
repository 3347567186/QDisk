# 打包与发布

更新：2026-11-16 · 对应 Tauri 1.8.0（替代已废弃的 pywebview 打包方案，旧文档见 `docs\02-历史-旧版\打包与发布_旧pywebview版.md`）

## 1 目录与产物

```
D:\Tools\TidyAssistant\
├── tidy-assistant.exe          运行副本（构建产物）
├── WebView2Loader.dll          WebView2 加载器，必须和 exe 同目录
├── 引擎\                        随包 Python 引擎
│   ├── 整理助手引擎.exe
│   ├── indexwalk.exe            Rust 索引遍历器（可缺省，缺了自动退回 Python 遍历）
│   ├── _internal\              依赖（不可删，删了引擎起不来）
│   └── 数据位置.json            运行时由 main.rs 写入
├── src\src-tauri\              Rust 外壳
├── src\web\                    前端（无构建步骤，frontendDist 直接指向它）
├── src\engine\                 Python 引擎源码
│   └── walkr\                  indexwalk 的 Rust 源码（零依赖，只做目录遍历）
├── release\                    NSIS 安装包 / 便携 zip
└── tools\cargo-tauri.exe       Tauri CLI（全局没有 cargo tauri）
```

## 2 一条命令构建

```powershell
.\build.ps1              # 默认全量：重建 exe + 打 NSIS 安装包 + 打便携 zip
.\build.ps1 -Bump patch  # 先递增版本号（patch|minor|major）再全量构建
.\build.ps1 -Version 1.1.0   # 直接指定版本号
.\build.ps1 -AppOnly     # 只重建 exe，不打包（临时验证能不能编译时才用）
.\build.ps1 -Bundle      # 只补打 NSIS 安装包到 release\
.\build.ps1 -Engine      # 只重建 Python 引擎
.\build.ps1 -Portable    # 只补打便携 zip（用当前 exe + 引擎）
.\build.ps1 -Clean       # 先清构建缓存
```

**默认就是全量**（2026-11-19 起）。1.35.x–1.36.x 期间默认只重建 exe，
`release\` 里的安装包一直停在 1.34.1，用户装完看不到新功能——所以把打包并进了默认动作，
要省时间才显式加 `-AppOnly`。

**引擎会自动跟上。** 默认全量/`-Bundle`/`-Portable` 在开跑前会比对
`src\engine\` 下的源文件与 `引擎\整理助手引擎.exe` 的时间：源码更新就先重建引擎再打包。
打包结束后产物自检会**再查一次**，仍过期就直接判构建失败。

这条是拿两次真实事故换来的（1.39.0 的 `rules.explain`、1.40.0 的 `search.top`
在真机上都 404）：旧脚本里只有 `if ($Engine) { Build-Engine }`，
默认全量根本不动引擎，而日志一片绿，看上去什么都对。
所以现在不要靠「记得加 `-Engine`」，靠脚本自己判断。

`-Bump` / `-Version` 会同时改写 `tauri.conf.json` 与 `Cargo.toml` 的版本号，产物名、安装包名都跟着变；
每次构建结束还会清理 `release\` 里第三旧及更早的包（只留最新 + 上一版）。规则见
`docs\01-当前版\版本管理与发布规范.md`。

脚本做的事，等价于手工命令：

```powershell
$env:RUSTUP_TOOLCHAIN = 'gnu-d'
$env:CARGO_HOME       = 'D:\Tool\cargo-ascii'
$env:CARGO_TARGET_DIR = 'D:\Builds\tidyassistant-target'
$env:Path             = 'D:\Tool\binutils\mingw64\bin;' + $env:Path
cd D:\Tools\TidyAssistant\src\src-tauri
D:\Tools\TidyAssistant\tools\cargo-tauri.exe build --bundles nsis
```

产物：`D:\Builds\tidyassistant-target\x86_64-pc-windows-gnu\release\tidy-assistant.exe`；
安装包在 `...\release\bundle\nsis\TidyAssistant_1.0.0_x64-setup.exe`。

## 3 为什么这些路径不能改

| 约束 | 原因 | 症状 |
|---|---|---|
| 全路径 ASCII | GNU 工具链的 `dlltool` 处理不了中文路径 | `dlltool: Can't create .lib file ... No such file or directory`，编译直接失败 |
| 构建缓存也在 ASCII 目录 | 同上，`CARGO_TARGET_DIR` 里带中文同样炸 | 同上 |
| exe 所在目录 ASCII | WebView2 用户数据目录按路径派生 | 启动即退，错误码 `0x800700AA` |
| 不再建 junction | 旧工作区在中文目录，才需要 `D:\Tool\tidy-src` 这种 ASCII 壳；现在源码本来就在 ASCII 路径 | 多一层链接是历史包袱 |

`%TEMP%` 在本机落在 DeepSeek Harness 的安装目录下（带中文），**不能**拿来当 target。

## 4 引擎重建

```powershell
.\build.ps1 -Engine
```

脚本会依次做三件事：编译 `src\engine\walkr`（Rust 索引遍历器，336 KB）→ 用 `D:\Builds\engine-venv` 跑 PyInstaller → `/MIR` 同步到 `引擎\`。

- **必须用带齐依赖的 venv 打包**。裸解释器里只有 pyinstaller，PyInstaller 找不到 PIL / docx / pypdf 时会静默跳过，打出来的引擎看着能跑、实际缺能力。venv 的建法：

  ```powershell
  uv venv D:\Builds\engine-venv --python <cpython-3.11.15>
  uv pip install --python D:\Builds\engine-venv\Scripts\python.exe pyinstaller==6.22.3 `
    pillow python-docx pypdf pystray pdfminer.six docx2txt exifread rich pydantic pywin32 attrs
  ```

  脚本找不到 venv 会退回 `py -V:3.11` 并打印黄色警告。
- **必须用 CPython 3.11**：`_internal\python311.dll` 与各类 `cp311-win_amd64.pyd` 都是 3.11 ABI。
- 复制用 `/MIR /XF 数据位置.json`：`/E` 不删陈旧文件，历史上正是因为这一点，`引擎\` 里堆积了 30 MB 根本不会执行的旧依赖（见 1.8.0 变更）。`数据位置.json` 是运行时状态，必须排除。
- 体积基线 **29.1 MB 左右**。想再动 spec 前先看 `整理助手引擎.spec` 顶部那段注释：tkinter / pystray 已由 Tauri 外壳接管，rich / pdfminer / docx2txt / exifread / pydantic 在 `tidy.py` 里零引用，`cryptography` 只服务「加密 PDF 抽文本」这一种边缘情况（缺了退化为空文本，不报错）。**不要排 `socket` / `select` / `asyncio`**：PyInstaller 的 `pyi_rth_multiprocessing` 启动钩子会 import socket，排掉之后引擎连 ping 都起不来。`ssl` / `_ssl` / `_hashlib` 可以排（已实测 27 个 RPC 方法全程不 import ssl；hashlib 走内置 `_sha1`/`_blake2`）。**`lxml` 不能排**：python-docx 靠它解析 XML，排掉之后 `.docx` 抽文本会静默返回空串，而 `extract_text` 吞异常、冒烟也看不出问题——必须用归档清单核对。
- 复制前脚本会停掉运行中的引擎：文件被占用时 robocopy 默认一直重试，表现为构建挂住十分钟。现在加了 `/R:2 /W:1`，占用超过两次重试直接报错。
- **改完依赖必须跑冒烟**：`python tools\smoke_engine.py`。它把打包后的引擎当 RPC 服务，依次调 `ping`/`scan`/`scan(use_content)`/`organize`/`shots.scan`/`cache.list`/`apps.list`/`search.index`/`search.query`/`migrate.plan`/`undo`，输出 12 行 `[OK]/[FAIL]`，任何一行失败都说明裁掉了不该裁的东西。

## 5 安装包（NSIS）

`tauri.conf.json` 关键字段：

- `bundle.targets: ["nsis"]`、`installMode: currentUser`（无需管理员）、`languages: ["SimpChinese"]`
- `bundle.icon: ["icons/icon.ico"]`（相对 `src-tauri\`）
- `bundle.resources: { "../../引擎": "引擎" }`（相对 `src-tauri\`，链到仓库根的 `引擎\`）
- `identifier: com.tidy.assistant`、`productName: TidyAssistant`

安装位置 `%LOCALAPPDATA%\TidyAssistant`（ASCII，WebView2 要求）；数据在 `%LOCALAPPDATA%\整理助手数据`，卸载不删数据。

## 6 验收清单

构建完逐条过一遍，别只看退出码：

1. `tidy-assistant.exe` 双击能起，无黑色终端窗口（`windows_subsystem = "windows"` 已生效）。
2. 引擎连上：任务管理器有 `整理助手引擎.exe`，`%LOCALAPPDATA%\整理助手数据\logs` 有新日志。
3. 卸载页能出列表（桌面 App / 商店 App 两个分类都要能切）。
4. 整理 8 个文件 → 撤销 → 文件原样回来。
5. 托盘图标存在，右键四项菜单可用。
6. 安装包装到 `%LOCALAPPDATA%\TidyAssistant` 后能启动（这一步才能验证 `resources` 打包是否成功）。

## 7 发布

```powershell
.\build.ps1 -Bump patch -Bundle -Portable
```

- `release\TidyAssistant_<版本>_x64-setup.exe`：给装机的用户
- `release\整理助手_<版本>_便携版.zip`：解压即用，含 `使用说明.txt`

**版本号是硬性要求**：每次改动都要递增（`patch` 修 bug / `minor` 新功能 / `major` 架构换代），
`release\` 只保留最新版与上一版，脚本自动清理更旧的包。完整口径见
`docs\01-当前版\版本管理与发布规范.md`。

发版前把本次改动写进 `docs\01-当前版\变更记录.md`（版本号、日期、要点、已知问题）。
