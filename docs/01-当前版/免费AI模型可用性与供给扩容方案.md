## 0. 执行摘要

用户痛点有两条，根因不同，必须分开解决：

1. **「免费模型少」** —— 数据层问题。当前模型池是一份过期静态快照（64 家厂商中仅 10 家标记为 free）。一次性可改善。
2. **「免费模型不稳」** —— 运行时层问题。两种表现都占：已配 key 的端点被限流、找不到能用的免费端点。免费额度经济的本质决定它**只能缓解，不能根除**。

核心判断：**免费模型不可能同时做到「又多、又稳、又免费」。** 方案目标不是消除不确定性，而是**吸收不确定性**——让候选面足够广、挂了能秒切、永远有兜底。

路线决策：**一个 OpenRouter key 统一接入**（一个 key 拉大免费候选面，申请摩擦≈0）+ **Ollama 本地兜底**（打破单点相关性，确定性保底）。放弃逐家申请 key 作为主体路线，仅保留为可选逃生舱。

方案分四层、四个版本落地，每版独立 `-Bump`、独立走全量测试门禁。**本方案不涉及任何代码改动，须获批后实施。**

## 1. 背景与问题定义

### 1.1 用户原话与确认
- 「免费模型少且不稳定，能否增加更多免费模型并确保可用」。
- 追问后确认：不稳定**两种都占**——① 已申请 key 的端点被限流；② 找不到能用的免费端点。
- 明确同意：**愿意配置本地 Ollama 兜底**。

### 1.2 问题拆分（第一性原理起点）

| 表象 | 本质 | 可解性 |
|---|---|---|
| 模型少 | 静态清单过时、free 标记仅 10 家 | 数据层，一次性可改善 |
| 找不到能用的 | 缺可见化入口、缺可用候选 | 数据 + UI，可改善 |
| 已配 key 被限流 | 免费额度共享、限流、时段降级 | 运行时层，只能缓解 |
| 整体不稳 | 候选间共享上游、单点相关 | 架构层，靠冗余 + 兜底吸收 |

## 2. 目标与非目标

### 2.1 目标
- **G1 扩大供给**：把免费候选数量从「10 家静态快照」提升到一个 key 可拉取的完整 `:free` 池。
- **G2 降低全灭概率**：任一时刻「无任何可用模型」的概率尽可能低。
- **G3 快速失败恢复**：某个候选限流/失效时，自动切换到下一个可用候选，用户无感或轻感。
- **G4 确定性兜底**：外部服务全部不可用时，本地 Ollama 保证能力不中断。
- **G5 用户可见可控**：用户能看到「有多少免费候选、当前用的是谁」，保留手动选择权。

### 2.2 非目标（明确不做）
- 不追求「免费模型 100% 稳定」——经济上不成立。
- 不自动替用户挑模型。
- 不引入第四常驻进程、不打包第三方网关。
- 不改动 Rust 运行时（除非条件性版本 4 触发，默认不做）。

- `src\web\js\ai\pool.js`：共 **64 家厂商**，`free:true` 仅 **10 家**（bazaarlink / byteplus / gemini / kilo / kimchi / nvidia_nim / ollama_cloud / opencode / opencode_zen / open_router）。

- **结论**：可配置级私用（`http://127.0.0.1:3001/v1`），**不进发行包**——第四常驻进程 + 双包门禁/ASCII/中文 TEMP 负担 + ToS 风险 + 与现有模型池功能重叠。

## 4. 第一性原理分析

### 4.1 目标函数
```
P(可用) = 1 − P(所有候选同时不可用)
```
若每个候选独立不可用概率为 `p`，候选数 `n`：
```
P(全灭) = p^n
```

### 4.2 四个杠杆（按性价比排序）
| 杠杆 | 数学作用 | 代价 | 是否烧额度 |
|---|---|---|---|
| 扩大候选数 `n` | `p^n` 指数下降 | 数据层一次性工作 | 否 |
| 确定性兜底（Ollama） | 相当于 `p≈0` 且与外部不相关 | 用户已同意配置 | 否 |
| 被动学习（失败即记住） | 提高选到可用者概率 | 纯记录、零请求 | 否 |
| 主动探测 | **不改变 p**，只改变「知不知道」 | 每候选一次请求 | **是，且判断失真** |

**推论**：主动探测是唯一「烧额度还不改变 p」的手段，予以删除。用户「找不到能用的」也占——探测再勤也不会凭空多出可用端点。

### 4.3 诚实边界【预测】
`p^n` 假设候选独立。现实中多家免费端点可能共享上游、同时段集体收紧，候选间正相关，实际 `P(全灭)` 高于 `p^n`。**这正是 Ollama 兜底不可省略的原因**——它的 `p` 与外部服务不相关，是唯一能打破相关性的东西。

### 4.4 路线选择的数学含义
- **每家 key 直连**：`n` 受申请摩擦限制（往往 2–3 家），但独立性较好，`p^n` 近似成立。
- **OpenRouter 统一 key**：`n` 一次性做大，申请摩擦≈0，但**单点网关**使候选高度相关，`p^n` 严重失效。
- **本方案**：取 OpenRouter 的「大 n + 低摩擦」，用 Ollama 兜底补上「独立性」缺口。

## 5. 路线决策：一个 OpenRouter key 统一接入

### 5.1 决策结论
主体路线 = 一个 OpenRouter key。逐家 key 降为可选逃生舱（第二供给源）。

### 5.2 关键论据

**【事实】直连不需要中转。** `https://openrouter.ai/api/v1` 天生是 OpenAI 兼容端点，现有请求链填一个 endpoint + 一个 key 即可用。此前担心的「中转站」是两件事——网络不通要架代理、多 key 池化网关（FreeLLMAPI 类）——直连都不涉及。

**【需自证】网络可达性。** 用户环境能否直连 OpenRouter 无法从代码判断。方案把「可达性验证」设为版本 1 第一步，不通则触发逃生舱（退回每家 key）。

**【判断】单点风险靠架构对冲，不靠放弃路线。** 单点相关性是真实风险，但 Ollama 兜底 + 可选第二供给源足以对冲。相比逐家 key 的申请摩擦（可能导致 `n` 永远上不去），OpenRouter 的供给确定性更高。

**【预测·最大风险】申请摩擦的反向风险在这里变成「单点依赖」。** 用户所有免费能力集中于一家网关的可用性与政策。缓解：Ollama 绝对必选 + 保留逃生舱。

### 5.3 两条路线对比（存档）
| | 一个 OpenRouter key（选定） | 每家各自 key（逃生舱） |
|---|---|---|
| 候选数 `n` | 一次做大 | 受申请摩擦限制 |
| 申请/维护成本 | 极低 | 高 |
| 候选独立性 | 差（单点相关） | 好（去中心化） |
| 网络/政策依赖 | 强 | 分散 |

## 7. 分层详细设计

### 层 1 · 供给扩容（纯数据 + UI）
1. 用 `/v1/models` 一次性拉取全部 `:free` slug，生成本地清单（**数量以实测为准，不写死**）。
2. `gen-ai-pool.ps1` 升级为「可重跑 + 版本戳 + 一次『能否列出模型』轻校验」——**不探活、不烧额度**。
3. 设置页（`settings.js:989-1118`）补「只看免费」筛选 + 「一键带入 endpoint/model」+ 显示「当前免费候选数」。
4. OpenRouter key 做成可填可改，复用 `keyFor` 同域名保护。
5. 版本 1 第一步验证网络可达性；不可达则跳逃生舱。

### 层 2 · 被动学习（纯前端，零额外请求）
核心思想：**把每次本来就要发的真实调用的结果，变成资产。**

1. **失败分类**（关键）：
   - 打标类：402（额度不足）/ 429（限流）/ 5xx / 连接超时。
   - 不打标类：401（key 错）/ 404（slug 错）/ 400（请求体错）——归为用户配置问题，明确提示，不惩罚候选。
2. **聚合粒度 = slug 级**（统一网关专属适配）：host 恒定，429 通常是「某个 `:free` 模型被限流」而非全网关挂掉，故按 slug 打标；host 作兜底。
3. **失败打标 + cooldown 软约束 + 指数退避 + 硬上限**（防永久拉黑）。
4. **成功学习**：成功记 `lastOk`（带 TTL），优先调度最近成功过的 slug。
5. **假成功检测**：`status=200` 但无 `choices` 或 content 为空 → 判失败（免费 slug 回空内容是常见边界）。
6. **持久化治理**：按 slug 聚合 + LRU（避开 caps 60 上限）；**只存 slug 标识、绝不存 key**；重启给宽限期清过期标记。

### 层 3 · Ollama 兜底（绝对必选，用户已同意）
1. `127.0.0.1:11434`（已存在）补配置引导。
2. 远程候选全在 cooldown 或连续失败 N 次 → 自动切 Ollama。
3. 全灭且 Ollama 未开 → 解除软约束、限频强制重试一个「最不坏」slug + 明确提示。
4. **能力明示**：UI 显示「当前使用本地兜底」，不自动替用户选模型。

### 层 4 · 红队对抗式审查
| # | 失效场景 | 后果 | 修正 |
|---|---|---|---|
| 1 | OpenRouter 单点故障/限流 | 全部免费模型同时挂 | Ollama 绝对必选 + 可选第二供给源 |
| 2 | 网络不可达 | 整体不可用 | 版本 1 先验证；不通触发逃生舱 |
| 3 | `p^n` 因高相关性失效 | 冗余没那么保险 | 承认边界，靠 Ollama 破相关性 |
| 4 | 429 是单 slug 限流 | 按 host 打标误伤全部 | 聚合粒度改 slug 级 |
| 5 | 免费 slug 下线/质量差 | 空/烂回答 | 假成功检测 + cooldown + 清单可刷新 |
| 6 | key 输错 | 打标害死正常网关 | 401 归配置问题，不打标 |
| 7 | 状态写入 key | key 泄露 | 只存 slug，复用 `keyFor` |
| 8 | 全灭强制重试 | 反向烧额度 | 限频 + 只重试一个 + 退避 |
| 9 | 大量 slug 撑爆 caps 60 | 状态丢失 | slug 聚合 + LRU |
| 10 | 免费池缩水/政策变化 | 清单过期 | gen 脚本可重跑 + 用户可刷新 |

## 8. 数据模型与状态设计

### 8.1 候选状态（AIStore，按 slug 聚合）
```
slug → {
  reason,          // 最近失败类型：402/429/5xx/timeout
  failAt,          // 失败时间戳
  cooldownUntil,   // 软约束到期时间
  lastOk,          // 最近成功时间（带 TTL）
  consecutiveFail  // 连续失败计数
}
```
- **不含 key**，只存 slug 标识。
- LRU 淘汰，容量对齐 `caps` 上限 60。
- 重启宽限：清除已过期的失败标记。

### 8.2 状态机（候选生命周期）
```
可用 ──402/429/5xx──> cooldown(指数退避) ──到期──> 待重试 ──成功──> 可用
  ↑                                                      │
  └────────────────失败则延长退避（达阈值标疑似下线）────────┘
```
- 401/404/400 不进入该状态机，直接提示用户。

## 9. 风险登记册

| 风险 | 等级 | 触发条件 | 缓解 |
|---|---|---|---|
| OpenRouter 单点故障 | 高 | 网关限流/故障 | Ollama 绝对必选 + 逃生舱 |

| caps 溢出 | 低 | slug 过多 | LRU |
| 版本/构建违规 | 高 | 未按门禁 | 每版 -Bump + build.ps1 + 标签 |

## 12. 明确排除项（贯穿所有版本）
- **不打包 FreeLLMAPI**；私用可配置级接入，不进发行包。
- **不主动探测、不做额度账本、默认不动 Rust**（V4 条件触发除外）。
